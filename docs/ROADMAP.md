## 阶段一：销售基础资料

按以下顺序一次实现一个功能：

1. `CUS-001`：客户档案、分类、标签与订单所需业务设置。
2. `PRD-001`：商品、SKU、多规格、上下架和删除保护。
3. `PRD-002`：客户价、等级价、基准价、价格上下限和调价。
4. `PRD-003`：授权方案、特殊授权和下单过滤。
5. `INV-001`：仓库库存、批次、可用量、出入库服务和流水。

顺序理由：新增订单依赖有效客户、可售 SKU、确定价格、商品授权和可用库存。先建立这些事实，可避免订单页面用临时数组复制规则。

阶段出口：能够为指定客户解析“哪些 SKU 可订、按什么单位和价格、当前是否有可用库存”，且结果可追溯。

## 阶段二：销售与资金闭环

1. `ORD-001`：客户订单列表、筛选、分页、详情和关联记录。
2. `ORD-002`：新增/修改订单、价格授权、预收占用和特价标记。
3. `ORD-003`：业务审核、财务审核和状态机。
4. `ORD-004`：销售出库、发货、库存扣减和差异单。
5. `FIN-003`：先建立资金账户、银行和结转基础。
6. `FIN-001`：客户应收、收款、账龄和核销；应收形成时点需先解决 OQ-007。
7. `ORD-005`：客户退单、退货入库和退款确认。
8. `ORD-006`：订单与销售统计。

阶段出口：黄金旅程“客户与商品 → 订单 → 审核 → 出库 → 应收 → 收款核销”可以从确定基线重复执行，失败时不存在半完成状态。

## 阶段三：采购与库存闭环

1. `PUR-004`：先建立供应商和商品供货关系，覆盖直送供应。
2. `PUR-001`：补货分析、智能采购和快速采购。
3. `PUR-002`：采购订单、审核和采购入库。
4. `FIN-002`：供应商应付、付款和核销。
5. `PUR-003`：采购退单与三重状态；开始前解决 OQ-002。
6. `PUR-005`：采购订单和出入库统计。
7. `INV-002`：转仓与其他出入库。
8. `INV-003`：盘点、成本调整与库存结转。
9. `INV-004`：加工配方、领退料与成品入库。
10. `INV-005`：订单/波次分拣和配送模拟。
11. `INV-006`：库存统计。
12. `FIN-004`：退款、内部转账和其他收支。
13. `FIN-005`：机构收款和资金统计。

阶段出口：黄金旅程“库存预警或销售需求 → 采购 → 入库 → 应付 → 付款核销”可以重复验收，库存变化均有单据和流水。

## 阶段四：组织与运营扩展

按依赖允许的顺序实施：

- 商品运营：`PRD-004` 铺货/订单模板、`PRD-005` 辅助资料。
- 客户经营：`CUS-002` 商机/常购、`CUS-003` 会员、`CUS-004` 地图/公海、`CUS-005` 外勤。
- 营销：`CUS-006` 优惠券/促销/内容、`CUS-007` 积分、`CUS-008` 企微模拟、`CUS-009` 商城原型、`CUS-010` 营销分析。
- 设置：`SET-001` 公司/部门/公告、`SET-002` 角色/员工、`SET-003` 区域/共享仓库、`SET-004` 系统日志。

阶段出口：不同模拟岗位看到正确菜单和操作，客户运营规则可验证，外部能力均明确标记为模拟。

## 中断后如何恢复

1. 阅读 `progress.md`，确认最近会话和“当前恢复点”。
2. 查看 `feature_list.json` 中唯一的 `in_progress`；没有则按本路线图选择下一项。
3. 打开对应 active plan 的“中断恢复点”，确认最后完成事项、下一动作和最近验证。
4. 阅读对应 product spec 与受影响架构文档。
5. 运行 `./scripts/init.ps1` 恢复可验证基线，再从下一动作继续。

如果三个状态来源不一致，先停止业务开发并修复记录：`feature_list.json` 决定功能状态，active plan 决定实施现场，`progress.md` 决定最近交接。
