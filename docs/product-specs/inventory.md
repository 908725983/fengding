# 库存领域规格

## 需求来源与事实边界

- 直接业务来源：[05-库存模块.md](../references/requirements/05-库存模块.md)；全局交互与角色资料来自 [01-整体架构与首页.md](../references/requirements/01-整体架构与首页.md) §4～§5。
- 功能切片、章节、依赖、规则归属和字段准备度以 [产品规格索引](index.md) 为唯一目录。
- `INV-01～INV-16` 直接整理自原文 §8。“不变量”中的原子性、幂等 ID、整数分和可控时钟属于 Harness 工程约束，不新增业务状态。
- 原始需求只明确出库时扣库存，没有订单预占库存规则；库存 Service 不得自行增加预占、释放或超卖策略。加权成本细节和“超储”状态边界分别按 `DEC-INV-001`、`DEC-INV-002` 处理。

## 目标与范围

以仓库、库位、批次和库存流水为中心，支撑销售出库、采购入库、转仓、盘点、加工、分拣和配送。所有数量变化必须可追溯到单据。

## 主要页面

- 库存/批次库存查询、出入库明细。
- 仓库与库位。
- 转仓、其他出/入库、盘点、成本调整、库存结转。
- 加工配方、计划、加工单、领退料和出成率。
- 待出库、订单/波次分拣、配送任务/线路/车辆、标签。
- 进销存和出入库统计。

## 业务规则

| ID | 必须行为 |
|---|---|
| INV-01 | 确认出库时扣减可用库存。 |
| INV-02 | 确认入库时增加库存。 |
| INV-03 | 可用库存小于出库量时禁止出库。 |
| INV-04 | 批次默认按生产日期先进先出。 |
| INV-05 | 可用库存小于等于安全库存时预警。 |
| INV-06 | 盘点期间禁止相关出入库操作。 |
| INV-07 | 入库时按加权平均法重算成本。 |
| INV-08 | 转仓分别确认源仓出库和目标仓入库。 |
| INV-09 | 保质期商品距有效期不超过 30 天时预警。 |
| INV-10 | 实拣不等于应拣时生成差异单。 |
| INV-11 | 加工前维护成品与原料配比 BOM。 |
| INV-12 | 加工领料扣减原料库存。 |
| INV-13 | 加工完工入库增加成品库存。 |
| INV-14 | 已结转月份禁止出入库。 |
| INV-15 | 入库可指定库位并支持分拣定位。 |
| INV-16 | 波次合并多订单，先按商品汇总拣货再分播。 |

## 不变量

- 可用量不得为负；现存量、待出库量和可用量的来源与关系受 `DEC-INV-003` 约束，不能把“待出库”偷换成未定义的订单预占。
- 每次库存变更必须生成包含业务来源、仓库、库位/批次、数量、单位、方向和时间的流水；命令接口与来源要求受 `DEC-INV-012` 约束。
- 同一 command 重试不得重复扣增；原型使用 request ID 验证幂等属于工程约束，但不能代替业务单据来源。
- 成本金额使用整数分；计算精度、舍入和计入成本范围必须等待 `DEC-INV-001`，不能由代码局部决定。

## P0 验收

1. 销售出库和采购入库分别正确扣增库存并生成一条流水。
2. 库存不足、盘点锁定、月份结转三种情况均由 service 拒绝。
3. 多批次出库按 FIFO 分配；临期批次触发预警；超储状态在 `DEC-INV-002` 决定阈值后验收。
4. 转仓第一步只减少源仓在途增加，第二步才增加目标仓可用量。
5. 重复提交同一 request ID 不重复改变库存。
6. 重置 Mock 后全部库存与流水恢复基线。

## 原型模拟边界

打印、扫码、车辆调度与真实定位只做交互模拟；加工和波次在主流程稳定后进入 P1。

### 状态与计算

- 数量行粒度推荐为企业×仓库×SKU；库位/批次余额汇总必须严格等于仓库 SKU 当前库存。规范库存单位、存储精度和显示换算受 `DEC-INV-004`。
- `当前库存` 是已确认入库减已确认出库的账面现存量；`待出库数量` 的订单来源、`可用库存=当前-待出库` 与 `在途数量` 的采购来源受 `DEC-INV-003`。
- `期初库存` 的“当期”、时区和快照来源未定义，受 `DEC-INV-010`。
- `安全库存` 规则明确为可用库存≤安全库存时预警；超储阈值和四状态优先级受 `DEC-INV-002`。
- 成本单价为只读快照；本切片不重算加权平均。库存金额、批次金额、负向流水金额和舍入受 `DEC-INV-001`。
- 批次状态明确包含正常/临期/过期；有效期当天边界、无有效期状态、批次唯一范围和 FIFO 同日排序受 `DEC-INV-008/009`。
- 过期批次禁止出库；库存不足必须由 Service 拒绝。是否要求所有库存必须在库位/批次中、非批次商品如何表达受 `DEC-INV-009`。
- 出入库流水一经写入不可编辑或删除；这是可追溯库存不变量。若业务需要冲销，必须由后续切片定义反向业务单据，不能修改历史流水。

黄金旅程设计：重置 baseline → 查看仓库 SKU 库存及详情 → 追溯库位、批次和流水 → 验证临期/过期状态 → 以同 request ID 重试模拟入库且只增加一次 → 预览 FIFO 出库并验证库存不足/过期拒绝 → 修改安全阈值观察状态 → 新增仓库和库位 → 预览并原子导入库位 → 切换角色验证成本与写操作边界。全部阻塞决策、实现和证据通过前不得宣称本旅程完成。

### 已确认决策

- `DEC-INV-001`：本切片只读取每基本单位的成本快照；金额=`基本单位数量×每基本单位成本` 后四舍五入到分。加权平均的费用组成和入库重算继续由 `PUR-002/INV-003` 决定，`INV-001` 不实现成本变更。
- `DEC-INV-002`：阈值按仓库×SKU；安全下限必填非负，上限可空且填写时必须大于下限。状态按可用量依次判定：`=0` 零库存、`0<可用≤下限` 不足、`上限非空且可用>上限` 超储、其余正常；禁售/禁用另做可用性标记，不混入库存状态。
- `DEC-INV-003`：当前库存由库存流水维护；待出库和在途由未来订单/采购 provider 提供。当前 provider 未接入时两列显示“数据源未接入”，可用库存也显示 unavailable，不用0代替；对外库存能力在此阶段只返回当前库存，直到订单分配规则确认后再开放可出库量。

### 状态与计算

- 计划状态：`pending→processing→completed`，另有 `cancelled`；创建首张加工单进入 processing，累计已完成主产出达到计划数量后 completed。
- 加工单状态：`pending-picking→picking→processing→completed`；首次领料确认进入 picking，所有原料累计领足进入 processing，原子完工成功后 completed。领料单为 `pending-outbound→outbound`，退料单为 `pending-inbound→inbound`。
- 领料确认按 FIFO 原子扣减原料，过期、不足、SKU 盘点锁或 occurredAt 已结转月份均整单拒绝。退料按原领料批次和成本入库；`实际用量=累计已领-累计已退`。
- 完工把最后退料、成品入库、成本、加工状态和计划累计量放在同一 requestId/version 原子命令内；任何一步失败全部回滚。成品成本仅含实际耗用原料 FIFO 成本，不含人工/制造费用；多产出按百分比分摊，整数分余数归主产出，并更新仓库×SKU 移动均价。
- 出成率按加工单×产出×原料显示，`预计产出=该产出配方数量×实际用量÷该原料配方数量`，`出成率=实际产出÷预计产出×100%`，保留 2 位；预计产出为 0 时显示 unavailable。加工只写 Inventory 和审计，不履约订单、不创建 Finance 事实。

- 线路使用系统唯一编码和至少一个“名称+省市区+地址+顺序”站点；引用后禁删，修改只影响未来快照。车辆牌照唯一、固定车型加其他、整数千克载重，任务自动切换空闲/出车中，维修禁派。
- 员工与区域复用窄 provider/订单地址快照，缺失即 unavailable。管理员/仓库完整，销售主管只读且地址只到省市区、禁导出打印，业务员/财务拒绝。
- 所有写命令使用 requestId/version；订单/车辆竞争和 Inventory/Order/Finance 跨域失败原子回滚；完成事实不可改，地图/GPS/路径优化/真实打印保持 unavailable/fake。

### 页面与导航

七个独立路由加入库存二级导航：待出库、订单分拣、波次分拣、配送任务、配送线路、车辆和分拣标签。列表筛选写入 URL，默认 30 条稳定分页；CSV 导出当前完整筛选结果。打印必须先预览并明确“原型模拟”。

### 筛选与列表

原文筛选字段全部保留；日期分别对应要求交货时间、分拣完成/创建时间、计划出发时间和标签创建时间。待出库状态来自分拣事实，不改写 Order 主状态。候选包含已审核和部分出库的剩余行；波次策略只预筛，待配送只纳入已完整出库且已分拣的送货上门订单。

### 表单与校验

- 分拣行展示订单保存的商品/单位快照，应拣、实拣、差异及 Inventory 当前库位/FIFO 建议；数量精度、null/0、超拣和库存副作用受 `DEC-INV-064`。
- 波次创建至少选择订单、仓库、策略和截止时间；聚合及分播守恒受 `DEC-INV-066/067`。
- 配送任务至少选择线路、司机、车辆、订单、计划出发时间和可选备注；候选与时间/唯一性受 `DEC-INV-069～071`。
- 线路至少包含名称、覆盖区域、一个有序站点、状态和可选默认司机/车辆/预计分钟；车辆至少包含唯一牌照、车型、正载重、状态和可选司机/备注。具体校验受 `DEC-INV-072～074`。
- 标签打印选择模板、类型、正整数份数并预览；商品/箱标签数量来源受 `DEC-INV-068`，不得自行计算箱规。

### 详情与操作矩阵

原文操作包括开始分拣、生成波次、打印、开始/完成配送、线路停用和车辆编辑。管理员、仓库、销售主管、业务员、财务的查看/管理/导出/打印/确认出库/确认发货及地址遮蔽受 `DEC-INV-075`；任何 UI 隐藏都必须有 Service 与路由同层拒绝。取消、删除、重开和完成后纠错分别受 `DEC-INV-063/071/072/076`。

### 状态与计算

- 原文给订单分拣和波次分拣的待分拣/分拣中/完成，以及配送待配送/配送中/完成，但没有精确动作；由 `DEC-INV-063/067/070` 固定。
- 行差异=`实拣-应拣`，`INV-10` 要求不等时自动形成差异单；与 ORD-004 canonical 短装差异的关系由 `DEC-INV-065` 固定。
- `INV-16` 要求波次按 SKU 汇总后再分播；汇总实拣必须等于全部订单分配之和，短缺归属不得静默自动决定。
- 分拣不改变或预占库存；显式确认出库才调用 Order canonical command。配送开始调用 canonical 发货并形成既有应收，配送完成不代替客户签收。

### 页面状态与 Mock

L3 计划覆盖 normal、empty、error/retry、permission-denied、boundary 和 concurrent；公共 slow 由共享异步设施覆盖。Order、员工或区域 provider 缺失时按 unavailable 显示；只有同时聚合多个可独立失败 provider 的页面才使用 partial-failure。真实地图/GPS/路径优化/打印机为 unavailable/fake，不发送网络请求。

### 验收追踪

- `INV-10`→`DEC-INV-064/065/076`：分拣数量、自动差异、canonical Order 差异、幂等和回滚。
- `INV-15`→`DEC-INV-064`：库位/FIFO 建议和确认出库重新校验，不把分拣误写成库存移动。
- `INV-16`→`DEC-INV-062/066/067`：同仓唯一占用、策略候选、SKU 汇总和人工分播守恒。
- 配送与既有销售闭环由 `DEC-INV-069～071/075/076` 追踪；从本次新建订单开始记录订单、分拣、出库、配送、发货和应收关联编号，证明库存只扣一次、应收只形成一次。

## ORD-005 客户退货入库集成契约（ready）

订单原文要求客户退单审核通过后手工创建类型为“退货”的其他入库单并关联退单号；库存流水类型明确包含“客户退单入库”。`ORD-005` 可以消费 INV-001 已有幂等入库 command，但不能直接改余额，也不能借此实现盘盈、赠品和其他入库的 `INV-002` 通用页面。

退货入库命令至少需要 `requestId/sourceType=customer-return/sourceId/operatorId/occurredAt/warehouseId/locationId/skuId/quantityMilli/costPerBaseUnitCents` 以及追踪商品的批次、生产和有效期。成功必须追加不可变库存流水并向 Order 返回 movement 引用；Order 与 Inventory 写入必须原子，任何一行、仓库/库位、批次、版本或权限失败时全部不生效。

用户于 2026-08-14 确认全部推荐方案：审核后由仓库在退单仓库内选择启用库位，一次整单精确入库，不支持部分或差异收货；追踪商品沿用原出库批次、生产日期、有效期和原出库流水成本，非追踪商品使用系统批次；退款前可因 1～200 字原因整张精确作废并恢复待收货，退款后禁止作废。作废时库存反向流水、Finance 贷项冲销/待退款关闭和 Order 状态恢复为一个三仓事务；重入库生成新资金记录。仅开放 `sourceType=customer-return/customer-return-void` 的窄 public command，不借此开放 `INV-002` 通用页面。

### 已有直接事实

- 数量按 `DEC-INV-004` 使用基本单位整数毫数量；SKU 行可按商品库存场景单位格式化，但计算不得使用浮点。
- 每次实际库存变化均形成 `InventoryMovement`，包含方向、仓库、SKU、批次、数量、成本、来源、requestId 和 occurredAt；订单/采购累计状态不能替代库存移动。
- 成本调整形成不可变 `InventoryCostHistory`，库存结转保存仓库×SKU 的月末数量、平均成本、金额和来源版本快照。
- 超级管理员和仓库人员可查看库存与成本；销售主管只读且遮蔽成本/金额；业务员和财务不可进入库存。原文没有库存统计导出权限，本切片不增加导出。
- 四报表使用一个 `/inventory/statistics` 路由和四个 Tab；报表、筛选与页码进入 URL，默认 30 条且可选 10/30/50/100。这是沿用全局列表规则和不改变业务语义的工程约束。

### 已确认统计口径

- 日期按 Asia/Shanghai 含首尾自然日，默认当月 1 日至 Mock 当前日，开始不得晚于结束。
- 只纳入不可变 `InventoryMovement`；按真实方向覆盖全部来源，反向流水按方向纳入，转仓来源/目标仓分别计出/入。
- 移动账本是期初/期末数量唯一来源；期初为开始日前累计净移动，期末为结束日及以前累计净移动。已结转月末必须与 closing snapshot 一致，冲突时整份报表 unavailable。
- 每条移动金额=`quantityMilli×costPerBaseUnitCents÷1000` 四舍五入到分；期初/期末价值为累计入库金额减累计出库金额，再叠加生效成本历史 `valueDeltaCents`。成本调整不进入本期入/出库额。
- 入出库笔数按 `direction + warehouseId + requestId` 去重；多 SKU/批次不重复，转仓两端分别计一笔。
- SKU 行按基本单位展示；仓库和卡片跨商品累加基本单位毫数量，并明确标注为“跨品项基本数量合计”。
- 名称、规格、单位和分类读取当前商品主数据；缺失时保留 SKU ID 并标记资料不可用，分类筛选不把未知资料静默归入其他分类。
- 任一期初、入、出、期末数量或金额非零即保留，全零行省略；停用仓库和已删除商品的历史事实仍保留。
- 未结转历史期间允许查看并显示“结果可能变化”；已结转月份标记并校验快照；报表只读，不自动结转。

使用一个 `/inventory/statistics` 路由和四个 Tab：进销存统计、按仓库进销存汇总、出入库汇总、库存收发仓库统计。`report/fromDate/toDate/warehouseId/categoryId/page/pageSize` 进入 URL；切换 Tab 或筛选时页码回到 1。原文没有库存统计导出操作和权限，本页面不增加导出按钮。
