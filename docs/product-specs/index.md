# 产品规格索引

本目录保存蜂订系统已经登记并逐步固化的产品行为。本页是功能切片、需求来源、依赖和规格准备度的唯一目录；长期顺序见 `../design-docs/implementation-sequence.md`，实施状态与证据见 `../QUALITY_SCORE.md`，当前现场见 `../exec-plans/active/`。登记在本页不等于已经可以编码，只有 `ready` 才表示字段与交互契约完整。

## 事实等级与冲突规则

1. 用户最新明确决定必须先写入相关产品规格和 active plan，写入后才成为仓库事实。
2. `../references/requirements/` 是用户提供的上游业务资料；产品规格是从上游资料提取、供实现使用的当前契约。
3. 上游资料与产品规格不一致时不得擅自选一个，必须建立人工决策项并暂停受影响行为。
4. `ARCHITECTURE.md`、`FRONTEND.md` 等工程文档可以规定实现安全性和一致性，但不能新增业务状态、字段、默认值或计算口径。
5. 竞品截图只提供风格线索；行业常识、模型记忆和“通常这样做”都不是业务事实来源。

## 字段与交互契约门禁

`source-only` 切片只能进入规格提取阶段，不得直接编写业务页面或 Service。把切片改为 `ready` 前，必须在对应领域规格中新增标题为 `## <功能ID> 字段与交互契约` 的章节，并逐项登记：

1. 精确原文文件、章节和必要的全局规范章节。
2. 路由、页面、Tab、弹窗或抽屉的范围以及明确非目标。
3. 筛选项：字段、控件、选项、默认值、清空行为、是否进入 URL；原文未定义则写“未定义”。
4. 列表：列名、类型、单位、格式、排序、分页、合计、权限和空值表达。
5. 表单：字段标识、类型、必填、默认值、校验、来源、是否只读、联动和保存结果。
6. 详情：信息块、状态、Tab、关联单据、操作日志和下一步动作。
7. 操作矩阵：操作、可见角色、允许状态、前置校验、副作用、确认文案、成功与失败结果。
8. 状态机和计算：枚举、合法转换、操作者、金额/数量公式、舍入、时区和边界。
9. 页面状态：loading、empty、success、error、retry、permission-denied、slow 和部分数据失败。
10. Mock 契约与验收：正常/边界/失败数据、业务规则 ID、自动测试和人工黄金旅程。

每个子章节必须写出实际结论或有证据的“不适用”，不能只保留标题。出现“未定义”时必须同时引用本页真实存在的 `DEC-*` 决策，并写明它阻塞的字段或行为；尚未登记的缺口先新增决策。在相关决策仍为 `open` 时保持 `source-only`，或先正式拆出不受影响的新切片，不能直接把原切片标为 `ready`。`ready` 只代表规格可实施，不代表代码、Mock 或页面已完成。

章节结构固定为：

```markdown
## CUS-001 字段与交互契约
### 事实来源
### 页面与导航
### 筛选与列表
### 表单与校验
### 详情与操作矩阵
### 状态与计算
### 页面状态与 Mock
### 验收追踪
```

禁止用占位词“按常规处理”“合理默认”“参考竞品”“等”替代契约。原文没有答案时登记人工决策，不得把猜测写成字段默认值或业务规则。

## 使用规则

- AI 先从本页选择依赖均已 passing 的下一切片，再按 `../PLANS.md` 建立 active plan。
- 规格提取可以在 `source-only` 阶段进行；进入实现阶段前必须达到 `ready`，并解决所有阻塞该切片的 open 决策。
- 每次只提取和实现一个切片，不提前为后续切片编造字段。
- 上表是当前已发现缺口，不是“未列出就可以猜”的白名单；规格提取发现新的未定义、冲突或多义内容时，必须先新增 `DEC-*` 行。
- 状态流转、金额、库存、权限和跨单据关系变化时，必须同时更新原始来源映射、规则、契约、测试和质量证据。
