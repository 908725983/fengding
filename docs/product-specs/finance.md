# 资金领域规格

## 需求来源与事实边界

- 直接业务来源：[07-资金模块.md](../references/requirements/07-资金模块.md)；业务闭环、全局交互与角色资料来自 [01-整体架构与首页.md](../references/requirements/01-整体架构与首页.md) §2、§4～§5。
- 功能切片、章节、依赖、规则归属和字段准备度以 [产品规格索引](index.md) 为唯一目录。
- `FIN-01～FIN-11` 直接整理自原文 §10。“不变量”中的整数分、原子流水和幂等属于 Harness 工程约束。
- 原文没有明确应收/应付形成时点，退款与退货入库的跨域账务关系也不完整，应付账龄区间和逾期边界没有完整定义；相关集成分别按 `DEC-FIN-001～004` 处理。

## 目标与范围

跟踪客户应收、供应商应付、收付款、核销和资金账户，使业务单据与资金变化能够相互追溯。

## 主要页面

- 应收/应付列表、按单据/商品明细、账龄分析。
- 核销单列表、新增与明细。
- 收款、付款、退款确认、拉新提现。
- 资金账户、收支明细/汇总、结转、银行和在线支付设置。
- 内部转账、其他收支、机构收款和资金统计。

## 业务规则

## 不变量

- 金额为整数分；收付款、已核销、未核销三者关系必须精确且不可为负。
- 一次核销可匹配多张单据，但总核销额不得超过可用收付款额或单据未核销额。
- 账户余额变化和资金流水作为一个结果，重复请求不得重复入账。
- 原始业务单据、收付款与核销单之间可双向追溯。

## P0 验收

1. 收款可分配到多张应收，部分核销后余额正确；超额核销被拒绝。
2. 已核销收款不能删除或改金额，未核销草稿按权限可操作。
3. 确认收款只更新一次账户余额并生成流水。
4. `DEC-FIN-004` 明确起算日、应付区间和逾期规则后，账龄在模拟日期边界前后进入正确区间。
5. 结转月份的收付款、退款与转账均被拦截。
6. 退款显示原支付方式，改用其他方式时记录原因。

## 原型模拟边界

不接入微信、支付宝、银联、银行或真实打款；支付设置只展示配置流程，所有支付结果标记为模拟。

## ORD-004 到 FIN-001 的应收集成边界

当前状态：`ORD-004` 集成契约为 `ready`；完整 `FIN-001` 契约也已在 2026-08-14 完成决策写回并达到 `ready`。订单级确认发货形成一次应收，金额为订单保存的完整 `orderAmountCents`；不按出库单分摊整单优惠或运费，预收保持占用直至 `FIN-001` 收款/核销，签收不再形成资金结果。

- 资金领域拥有应收事实；订单只能通过公开幂等 command 请求形成应收，不能在订单聚合中复制第二套可编辑应收单。
- command 至少需要 `requestId/orderId/customerId/orderNo/orderAmountCents/occurredAt` 和订单/客户金额快照；在订单级确认发货时调用，客户自提的确认发货同样代表确认交付。
- 发货状态、订单全额应收记录和订单活动日志必须原子成功或失败；资金 provider unavailable/error 时不能先显示已发货再补账。未发货出库作废不碰应收，签收只完成履约。
- `FIN-001` 页面未完成期间可以使用明确标识的确定性 fake adapter 证明调用、幂等和回滚，但不得声称应收列表、收款、核销或资金账户已经实现。
- 差异仅在补发完成或忽略短装后允许发货；“退款”需要 `ORD-005/FIN-004` 的退款单、审核、账户与冲销契约，在此之前只能明确显示不可执行，不能记录“退款成功”或形成虚假应收。

### 筛选与列表

原文没有为资金账户、银行和结转定义关键字等筛选条件，当前不自行添加业务筛选。所有普通列表沿用全局默认 30 条/页和 `createdAt desc,id desc` 稳定排序；月份属于金额口径而非搜索条件。“当期”采用 Asia/Shanghai 受控时钟所在自然月，页面可切换已存在期间并写入 URL，默认当前月且未来月份不可选。

| 列 | 数据契约 | 显示规则 |

### 表单与校验

账户管理允许新增，字段为名称、现金/银行/微信/支付宝类型、启用状态、启用月份和首期期初余额。名称企业内唯一；已有流水或结转后类型不可改；不提供物理删除。除此之外还必须满足：

- 金额输入解析为整数分，最多两位小数；空值、非数字和超出安全整数拒绝，不用浮点累计。
- 账户类型只允许原文四类；名称、状态与期初不能通过页面临时数组保存。
- 期初余额不是普通资金流水；仅在账户没有任何流水且首月未结转前可改，之后更正等待 `FIN-004` 的可追溯调整单，不能直接重算历史。
- 账户写操作携带 `requestId/expectedUpdatedAt/operatorId/occurredAt`，幂等重放返回原结果，版本冲突要求重新加载。

银行资料允许新增、编辑和停用，固定包含关联银行资金账户、银行名称、账户户名、银行账号、开户行、对公/对私和启用/停用。账号去空格后企业内唯一且 4～64 字符；不臆造银行卡校验算法，不提供物理删除。停用后不可用于新业务。银行账号按不可信敏感输入处理：页面不得写入 URL、日志或错误详情；仅管理员/财务查看完整值，销售主管只见后四位。

支付通道固定展示微企付和银联商务，不接收真实商户号、密钥、证书、银行卡、身份证或支付凭据。开通动作只创建明确标识“原型模拟”的本地申请，显示“模拟申请中”但通道仍为未开通；baseline 可显式展示已开通，不得发起网络请求、创建支付账户或改变余额。

### 持久化对象与公开边界

最终 schema 名称可以按代码风格调整，但不得省略以下事实：

- `FundAccount`：ID、企业范围、名称、四类账户类型、状态、启用月份、首期期初整数分、创建/更新时间、版本和操作者；不保存可被页面任意覆盖的“当前余额”。
- `FundMovement`：ID、账户、方向、金额整数分、发生时间、来源类型/来源 ID/单号快照、往来单位快照、摘要、操作后余额、requestId 和操作者；确认后不可编辑删除。
- `FinancePeriod`：`YYYY-MM`、状态、各账户期初/收入/支出/期末快照、结转/反结转审计和版本；从账套启用月开始连续结转。
- `BankProfile`：ID、唯一关联的银行类型资金账户、银行/户名/账号/网点/对公私/状态、版本和审计；不复制余额。
- `PaymentChannel` 与模拟申请：固定通道资料、真实开通状态及明确模拟记录；不得保存真实凭据。
- 所有账户聚合和结转请求保留幂等记录；fixture 使用明显虚构银行、账号和摘要。

资金领域未来向 `FIN-001/002/004` 暴露公开 command：校验账户启用、权限、发生月份未锁定、金额、余额不为负和幂等，然后原子追加流水并返回余额；不得允许其他领域直接修改账户 Repository。本原型不提供透支配置，任何扣减导致负余额都整体拒绝。查询 provider 必须区分 `available/unavailable/error`，不能把未知余额显示为 0。

### 状态与计算

已由原文固定的计算：

```text
期间期末余额 = 期间期初余额 + 期间收入 - 期间支出
下期初余额 = 已结转上期期末余额
```

- 所有金额为整数分；逐笔操作后余额按确定顺序累计，汇总必须能与最后一笔余额和期间快照对账。
- 只有确认后的未来收款/付款/转账/退款/其他收支才能写资金流水；本切片不把草稿或模拟支付申请计入余额。
- 账套保存启用月，只能从该月开始按月连续结转，未来月不可结转，空月可结转。一次请求原子冻结当月全部账户期末并生成下月期初，重复 requestId 幂等；对应月份的资金写 command 必须在 Service 边界拒绝。
- 只允许反结转最新已结转月且原因 1～200 字；存在更晚结转或其后任何资金流水时拒绝。成功原子移除派生下月期初、解除锁定并保留不可变审计。
- 账户停用不等于余额归零或删除历史；允许带余额停用和恢复，但停用期间不能承接新资金动作。
- 当前只支持一种账面币种还是需要币种字段，原文没有给多币种或汇率；本切片不增加多币种换算。若后续出现真实多币种需求，必须新建决策而不能重解释现有金额。

### 权限与字段遮蔽

细权限固定为 `finance.view-accounts`、`finance.manage-accounts`、`finance.view-ledger`、`finance.carryover`、`finance.manage-banks`、`finance.manage-payment-channels`。管理员和财务拥有全部；销售主管只有账户/流水只读且银行账号遮蔽；业务员和仓库不可进入资金账户区域。

- 直接调用 Service 越权时拒绝；页面隐藏按钮不能代替命令授权。

### 持久化实体与公开边界

- `CustomerReceivable`：企业、业务编号、来源类型/ID/单号、客户/联系人快照、订单结算与商品行快照、应收/运费整数分、形成时间、结算方式/账期快照、requestId、版本和审计；不保存可被页面覆盖的已收/待收。
- `CustomerReceipt`：企业、业务编号、客户快照、日期、金额、方式、账户/资金流水引用、订单可选引用、优惠、附件元数据、备注、正常/作废审计、requestId 和版本。
- `ReceiptWriteoff`：企业、业务编号、客户、核销日期、状态、总额、备注、操作人、requestId、版本及 `WriteoffAllocation[]`；分配行明确来源收款/预收、目标应收、现金核销/优惠核销金额。
- `CustomerPrepaymentLedger`：客户预收增加、订单占用、释放和核销消费的不可变记录；可用、占用与已用由流水计算，不允许页面直接改余额（`DEC-FIN-021`）。
- 收款采用 `normal/void`、核销采用 `active/cancelled`，应收状态从有效核销派生为 `open/partial/settled`（`DEC-FIN-018/019/024/025`）。
- Finance 是应收、收款、核销和预收余额的唯一 owner；Order 只通过 `public.ts` 创建应收和读取订单收款投影，Customer 只读取应收余额 provider（`DEC-FIN-017`）。
- 收款确认必须通过 FIN-003 `public.ts` 追加账户收入；作废若允许，只能通过公开反向 command 追加可追溯流水，禁止直接改 `balanceAfterCents` 或删除原流水。

| 导出应收 | 查询合法且有导出/查看权限 | 本地 CSV 与完整查询合计一致 | provider error 不生成空文件冒充成功 | `DEC-FIN-028` |

### 状态与计算

已确认且不依赖开放决策：

```text
应收待收 = 应收金额 - 有效核销金额
收款可核销 = 正常收款金额 - 已分配现金核销金额
每项金额均为非负安全整数分
有效核销总额 <= 来源可用额 且 <= 目标应收待收
```

- 应收的已收/待收只由有效核销分配计算；收款单存在不代表应收已经结清。
- 一个 requestId 只能对应一种 command；重放返回原结果，复用于不同动作则 `CONFLICT`。可变聚合使用版本或 `expectedUpdatedAt` 防并发超额核销。
- 收款资金流水的发生时间与收款确认时间一致，账户余额由 FIN-003 计算；核销本身不再次改变资金账户。
- 任何错误不得留下“有收款无流水”“有核销无分配”“发货成功但应收失败”或预收一边更新的现场。
- 账龄按上海自然日计算；形成日为第 0 天。预收、优惠、作废、取消和日期约束严格采用 `DEC-FIN-004/021/023/024/027`，不得由页面另行推导或放宽。

### 权限与敏感信息

细权限固定为 `finance.view-receivables`、`finance.view-receivable-details`、`finance.view-aging`、`finance.view-receipts`、`finance.manage-receipts`、`finance.view-writeoffs`、`finance.manage-writeoffs`、`finance.export-receivables`。管理员/财务全量，销售主管查询与导出只读，业务员/仓库无权；路由、UI、Store 和 Service 必须一致（`DEC-FIN-028`）。

联系人、电话、客户银行资料、附件和资金账户均按敏感信息处理。列表 URL、日志、错误和导出文件名不得含电话、账号或附件路径；管理员/财务看完整快照，销售主管电话遮蔽且导出一致（`DEC-FIN-029`）。附件只保留虚构元数据，不读取或上传真实文件内容。

## ORD-005 退单退款集成契约（source-only）

`ORD-005` 需要 Finance 提供退货应收贷项、退款义务、确认退款和订单/退单只读投影，但不允许 Order 直接修改 `CustomerReceivable`、核销、预收账、账户流水或期间。以下是原文已知边界：

- 确认退款列表显示退款单号、原订单号、客户、退单/售后类型、申请金额、实退金额、原路/余额/现金方式、申请时间、待审核/已退款/已拒绝和审核/退款/查看。
- 退款优先原支付方式，特殊情况可现金或余额；资金账户实时更新，已结转月份禁止资金出入，账户仍禁止负余额。
- 原应收、收款、核销和资金流水不可编辑或删除；退货必须追加可追溯调整，不能把原应收金额改小或把历史核销删掉。
- 普通客户退货遵循审核→退货入库→确认退款；短装差异退款没有入库事实，必须使用独立来源类型。

候选最小对象为 `ReceivableCreditAdjustment`、`CustomerRefund`、`RefundSourceAllocation` 和 `RefundRequestRecord`。贷项保存退单/差异来源、原应收、金额、发生时间与操作者；退款保存申请/实退、方式拆分、账户/预收来源、状态和审计。具体所有权、金额公式、来源拆分、余额恢复、状态、期间和纠错受 `DEC-FIN-003/031～036` 阻塞。

安全的不变量：累计贷项不超过原应收；调整后待收不小于 0；累计实退不超过可追溯真实现金或预收消费；优惠不形成现金退款；同一来源不重复退款；任一账户/期间/版本/跨域写失败时 Order、Inventory、Finance 全部恢复。开放决策未 decided 前，现有“付款与退款（后续切片）”和差异退款禁用状态必须保留。
