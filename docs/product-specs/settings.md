- 直接业务来源：[08-设置模块.md](../references/requirements/08-设置模块.md)；角色模块矩阵来自 [01-整体架构与首页.md](../references/requirements/01-整体架构与首页.md) §5。
- 功能切片、章节、依赖、规则归属和字段准备度以 [产品规格索引](index.md) 为唯一目录。
- `SET-01～SET-10` 直接整理自原文 §6。路由/UI/Service 三层检查和仓库 Provider 属于 Harness 工程约束。

## 目标与范围

提供企业、组织、账号、角色权限、基础资料和不可篡改操作记录，为所有领域提供统一配置。

## 主要页面

- 公司信息、部门树、内部公告。
- 角色列表/权限树、员工列表与账号。
- 区域树、仓库资料。
- 系统日志。

## 业务规则

| ID | 必须行为 |
|---|---|
| SET-01 | 始终保留至少一个系统管理员账号。 |
| SET-02 | 角色权限修改后，已登录用户重新登录才生效。 |
| SET-03 | 部门/区域下有员工或客户时不可删除。 |
| SET-04 | 开启公告推送后向员工移动端发送通知。 |
| SET-05 | 设置与库存共用同一仓库数据。 |
| SET-06 | 系统日志不可删除或修改。 |
| SET-07 | 同一企业内员工登录账号唯一。 |
| SET-08 | 员工首次登录必须修改初始密码。 |
| SET-09 | 区域支持多级树，用于客户分配与统计。 |
| SET-10 | 禁售仓库存不参与销售出库。 |

## 权限模型

原型使用 RBAC：模拟用户关联角色，角色关联菜单和操作权限。权限判断同时作用于路由、可见性和 service command；不能只隐藏按钮。超级管理员之外的默认角色细权限及数据范围在需求明确前只保留接口，不自行填入“合理权限”。

## 跨领域约束

仓库由库存领域持有唯一实体定义，设置页面通过公开仓库 provider 管理；禁止复制第二份仓库数据。公告推送使用 fake adapter；日志由各 command 追加且没有删除接口。

## P0/P1 验收

1. 无法删除最后一个系统管理员，也无法创建重复员工账号。
2. 有下属实体的部门/区域删除失败并列出原因。
3. 权限修改不改变当前会话，重新登录后菜单与 service 权限一起生效。
4. 仓库在设置和库存页面修改后保持同一份数据；禁售仓不进入销售可用库存。
5. 关键写操作生成日志，任何角色都没有删除/编辑日志操作。
6. 首次登录账号被引导修改初始密码。

## 原型模拟边界

不实现真实认证、密码加密强度证明、移动端消息到达和生产审计存储；界面必须标注这些属于模拟。
