# Dashboard 规格

## 需求来源与事实边界

- 直接业务来源：[01-整体架构与首页.md](../references/requirements/01-整体架构与首页.md) §3；全局交互与权限资料来自同文件 §4～§5。
- 功能 ID、依赖和字段准备度以 [产品规格索引](index.md) 的 `DASH-001` 为准。
- 原始需求明确的区域、字段和跳转属于业务事实；指标计算、聚合容错和 Mock 组织若原文未定义，只能作为明确标注的工程方案，不能冒充业务口径。
- `DASH-001` 为 `source-only` 时只能提取规格，不能实现未定义指标。

## 目标

让管理者和岗位人员进入系统后立即知道当前业务概况、需要处理的事情以及风险，不替代各领域的明细页面。

## 页面范围

- 待办事项：默认待办卡片及用户自定义待办。
- 营业情况：核心指标卡片、时间范围和趋势图表。
- 预警中心：库存、资金、业务异常等可跳转预警。
- 通知公告：展示有效公告及未读状态。

原型首版先实现待办、核心指标、预警与公告四区；复杂个性化布局不在首版。

## 行为约束

- 指标必须标注时间范围、单位和口径入口，不展示无法解释的数字。
- 待办按当前模拟用户权限过滤，点击进入对应模块的已筛选列表。
- 预警状态不能只用颜色；已处理项与未处理项可区分。
- 空数据、查询失败和无权限分别呈现。
- 原型数据由各领域 repository 汇总，Dashboard 不直接读取所有 fixture。

## 实现映射

- View：`src/features/dashboard/views/`
- Service：聚合各领域只读 provider，禁止在 Dashboard 修改业务单据。
- Mock：为管理员、销售、仓库、财务至少准备不同待办集合。

## 验收

1. 默认场景显示四个区域，指标含单位和时间范围。
2. 切换模拟角色后，待办数量和可见入口按权限变化。
3. 点击待办能进入正确目标及筛选状态。
4. `empty/error/permission-denied` 场景呈现不同反馈。
5. 1280px 下信息不重叠，关键待办无需横向滚动。

## 非目标与缺口

不实现实时大屏、自由拖拽布局或生产级数据分析。日界线、纳入状态、超时/风险阈值和同比环比边界按 `DEC-DASH-001` 决定，不能自行计算。
