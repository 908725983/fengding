# 采购领域规格

## 需求来源与事实边界

- 直接业务来源：[04-采购模块.md](../references/requirements/04-采购模块.md)；全局交互与角色资料来自 [01-整体架构与首页.md](../references/requirements/01-整体架构与首页.md) §4～§5。
- 功能切片、章节、依赖、规则归属和字段准备度以 [产品规格索引](index.md) 为唯一目录。
- `PUR-01～PUR-10` 直接整理自原文 §7。确定性补货算法、原子入库和跨域 Provider 是 Harness 工程约束。
- 原文没有明确应付形成时点，`PUR-06` 对原采购单使用“建议关联”，补货数量没有公式，订单状态与入库状态又存在两种表达；分别按产品索引中的 `DEC-FIN-002`、`DEC-PUR-001～003` 处理。

## 目标与范围

把库存或销售需求转成可执行采购单，并跟踪供应商、入库、退采与应付。包含补货分析、智能/快速采购、采购订单/退单、供应商、直送与统计。

## 主要状态

采购订单：待审核 → 已审核 → 部分入库 → 已完成。退单分别跟踪退单、出库、退款三个状态，不合并成单一模糊状态。

## 业务规则

| ID | 必须行为 |
|---|---|
| PUR-01 | 基于安全库存和缺货情况生成补货建议。 |
| PUR-02 | 补货分析可按库存或按订单一键生成采购订单。 |
| PUR-03 | 采购前必须存在供应商与商品供货关系。 |
| PUR-04 | 采购订单按规定状态单向推进。 |
| PUR-05 | 确认入库时增加目标仓库存。 |
| PUR-06 | 采购退货出库扣库存；建议关联原采购单且退货量不超过已入库量。 |
| PUR-07 | 退单保留退单、出库、退款三重状态。 |
| PUR-08 | 供应商直发客户单独标记和统计。 |
| PUR-09 | 采购单号格式为 `PO + YYMMDD + 6位序号`。 |
| PUR-10 | 快速采购支持单据、出库、收款状态和配送方式筛选。 |

PUR-06 中“建议关联”不是已确认的强制规则；若实现为强制校验，必须先取得业务确认并更新本规格。补货建议在 `DEC-PUR-002` 前只能展示输入字段或人工样例，不能声称已按业务公式计算。

## 跨领域约束

采购确认入库与库存增加作为一个结果；采购价格来自有效供应商供货关系；入库完成后形成应付的时点由资金规则协调。

## P0/P1 验收

1. `DEC-PUR-002` 决定并写回公式后，安全库存不足生成可解释的建议数量；决定前只验收字段与手工调整，不验收计算结果。
2. 无供货关系的商品不能生成采购单。
3. 单号格式正确；状态流转在 `DEC-PUR-003` 决定统一模型后验证，非法跳级由 service 拒绝。
4. 部分入库只增加实际数量并保持“部分入库”；全部入库后完成。
5. 采购退货库存不足时失败，三重状态分别可见。
6. 按库存/按订单场景可重复重置。

## 原型模拟边界

补货建议采用规格中可解释的确定性算法，不声称是智能预测；直送物流和供应商协同只模拟状态。

### 状态与计算

候选命令为 create、update、enable、disable。停用供应商后，既有关系与未来历史单据仍可查询，但后续采购候选必须拒绝该供应商；恢复启用不自动恢复已停用供货关系。物理删除、级联删除关系、修改历史采购快照都不在候选行为中。

每个修改命令携带 `expectedVersion` 和 `requestId`：版本冲突拒绝覆盖；相同 requestId 返回相同结果；成功后记录操作者、时间、动作和不含完整银行账号的摘要。以上业务取舍受 `DEC-PUR-008/018` 约束。

状态只允许 `enabled/disabled`，供应商与供货关系分别保存，不把“供应商停用”批量改写为“关系停用”。有效采购资格必须同时满足供应商启用、关系启用和 SKU 可用；首选约束只在有效关系中计算。同一 SKU 设置新首选时，在一个事务内取消旧首选并设置新首选。供应价以整数分保存且必须大于 0，页面只负责元/分转换。

### 供应商供货商品

页面左侧分类树来自 Product 分类，右侧按商品名称/编码、SKU 编码、规格和条码搜索。页面必须先选供应商，不能把不同供应商的价格混成一张无归属表。

| 字段 | 候选来源/规则 |
|---|---|
| `supplierId` | 当前供应商；必须启用才能新增关系 |
| `skuId` | 已存在 SKU；保存时读取商品/SKU 快照用于稳定列表 |
| `procurementUnitId` | SKU 的采购场景单位；关系不能私自改变 Product 单位配置 |
| `procurementUnitRate` | 保存当时采购单位对基本单位换算快照 |
| `supplyPriceCents` | 每采购场景单位的非负整数分；0 是否允许由边界决策约束 |
| `preferred` | 同一 SKU 最多一个启用首选关系的候选字段 |
| `status` | `enabled/disabled`；停用可恢复，不物理删除 |
| `version/createdAt/updatedAt` | 并发、排序和审计 |

候选唯一键为企业×供应商×SKU，一个 SKU 可由多个供应商供货。采购单未来必须复制供应商、SKU、单位换算和成交供应价快照；之后调价或停用不重写历史。自动采购只可使用启用供应商的启用首选关系；没有首选时明确要求人工选择，不按最低价或最近价猜测。

### 已确认方案（2026-08-19）

1. 本切片只实现供应商与供货关系；直送统计保留入口和完整字段目录，在 `PUR-002/003` provider 前显示 unavailable。
2. 编码企业内唯一且不可改，名称企业内唯一可改；保留购销/代销并新增入仓/直送/均可供货方式；账号不创建凭据。

并行保存三组状态：工作流 `pending-review/approved/completed/voided`，出库 `not-shipped/partially-shipped/shipped`，退款 `not-required/pending/refunded`。保存后为 `pending-review/not-shipped/not-required`；审核只推进工作流为 `approved`。审核后允许多次部分出库，累计出库量等于退单量且对应 Finance 贷项均完成后，工作流进入 `completed`。

每次退采出库从原采购目标仓的启用库位选择，由 `INV-001` 按 FIFO 扣减；累计超退单量或任一行库存不足时整体拒绝。采购域拥有退单工作流，库存域拥有余额、批次、库位和流水，资金域拥有应付、贷项和退款义务。跨域 coordinator 必须依次使用公开 provider，在采购、库存、Finance 三域建立快照；任一阶段失败时恢复三域快照，不得留下部分出库、孤立贷项或提前完成状态。

一张采购单多次入库时，退量按有效入库时间 FIFO 分配到对应应付分录，任何分录的累计贷项不得超过原入库数量和金额。Finance 贷项先冲待付，全部被待付吸收时退款状态为 `not-required`；超出待付的金额形成供应商退款义务并投影为 `pending`。用户于 2026-08-24 通过 `DEC-FIN-057` 确认：实际到账由 `FIN-004` 的独立供应商退款对象整笔确认，只能进入启用的 cash/bank 账户，必须处于开放期间，原子增加账户收入且累计不得超过义务；成功后采购投影为 `refunded`。PUR-003 不复制该命令。

待审核退单，或已审核但尚无任何有效出库/贷项的退单，可填写原因后整单作废；已有有效出库或贷项时禁止作废。本切片不实现反向退采、更正库存或撤销 Finance 贷项。直送退单在直送执行 provider 完成前明确 unavailable，不创建普通库存出库或虚构退单事实。

创建、审核、作废和出库使用 requestId 幂等；审核、作废和出库同时校验 expectedVersion。重复 requestId 返回同一结果，不重复编号、库存流水或贷项；版本冲突明确报错。查询丢弃过期响应；日志保存动作、操作者、时间、原因、requestId、来源采购单、库存流水和 Finance 贷项 ID，不记录完整敏感账号。
