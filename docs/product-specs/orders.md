# 订单领域规格

## 需求来源与事实边界

- 直接业务来源：[02-订单模块.md](../references/requirements/02-订单模块.md)；全局交互与角色资料来自 [01-整体架构与首页.md](../references/requirements/01-整体架构与首页.md) §4～§5。
- 功能切片、原文章节、依赖、规则归属和字段准备度以 [产品规格索引](index.md) 为唯一目录。
- `ORD-01～ORD-15` 直接整理自原文 §8。分层、整数分、原子提交、Mock 场景属于 Harness 工程约束，不表示原文已定义技术实现。
- 对应切片为 `source-only` 时只能提取契约；订单标签、库存预占、特价审批、预收占用、应收时点和退款跨域结果按索引中的人工决策门处理。

## 目标与范围

覆盖客户订单、客户退单、差异单、销售出库单、订单/销售统计。原型 P0 黄金旅程是“新增订单 → 审核 → 部分/全部出库 → 应收与收款记录”。

## 主要页面

- 订单：列表、筛选/批量操作、新增、详情、分享。
- 退单：列表、新增、详情与退款状态。
- 差异单：列表与详情。
- 销售出库：列表、详情、作废后重新出库。
- 统计：商品明细/汇总、客户汇总、出入库明细/汇总。

## 核心状态

正常销售状态单向推进；需求明确允许的例外仅为“待财务审核 → 待订单审核”。实现时状态枚举、允许动作和操作者权限必须位于 service/config，不散落在按钮判断中。

## 业务规则

| ID | 必须行为 |
|---|---|
| ORD-01 | 单号按“前缀 + YYMMDD + 序号”自动生成且不可编辑。 |
| ORD-02 | 正常状态不可回退；仅允许待财务审核回到待订单审核。 |
| ORD-03 | 实出小于应出时自动生成关联差异单。 |
| ORD-04 | 整单退和部分退均关联原订单。 |
| ORD-05 | 可退数量不得超过已出库数量。 |
| ORD-06 | 退款必须经过确认退款流程。 |
| ORD-07 | 确认出库时实时扣减可用库存。 |
| ORD-08 | 选择客户与商品后自动匹配客户等级价格。 |
| ORD-09 | 客户只能订购已授权商品。 |
| ORD-10 | 分享链接超过有效期后不可查看或确认。 |
| ORD-11 | 下单时自动占用客户预收金额。 |
| ORD-12 | 特价订单必须标记并进入特殊审批。 |
| ORD-13 | 作废出库单保留可查，并支持重新出库。 |
| ORD-14 | 订单自定义属性来源于设置配置。 |
| ORD-15 | 统计二维表支持配置展示维度。 |

## 跨领域约束

- 下单读取客户状态、商品授权和价格；任何校验失败都不能生成半成品订单。
- 确认出库与库存扣减是一个业务结果；失败时两者都不生效。
- 出库/签收形成应收的具体时点需按资金规格；未确认前不得自行决定。
- 原始需求没有库存预占规则；不得因为系统通常会预占库存而自行实现。
- `ORD-11` 没有给出预收占用金额和释放规则；`DEC-ORD-004` 决定前不得用“占满可用余额”等默认算法。
- 金额使用整数分，优惠、运费、预收占用和应收之间必须有可追溯明细。

## 实现映射

`src/features/orders/` 保存订单类型、repository、状态机 service、stores 和页面；库存、商品、客户、资金能力通过公开 provider 注入。

## P0 验收

1. 按客户、日期、单号、状态筛选订单，列表/分页/空结果正确。
2. 已授权商品带入正确价格优先级，未授权商品不可提交且说明原因。
3. 新订单单号不可修改，金额汇总以分计算并正确格式化。
4. 状态按允许路径推进；非法回退被 service 拒绝而非仅隐藏按钮。
5. 部分出库同时扣正确库存并生成差异单；库存不足整体失败。
6. 退货数量超过已出库数量被拒绝；退款需确认。
7. normal/error/slow/permission-denied 场景和订单黄金旅程测试通过。

## 原型模拟边界

分享、打印、导入导出、物流与收款通道只模拟结果。统计先用固定数据验证信息结构，未定义的指标口径不得声称真实准确。

### 表单与校验

`ORD-001` 没有新增/修改业务表单，只有查询、导出和模拟打印输入：

- 查询 Schema 对页码、枚举、日期顺序和金额顺序做运行时校验；金额文本按两位小数安全转整数分，不接受 `NaN`、负数或超出安全整数范围。
- `orderId`、选择集合和打印目标必须在 service 中重新校验存在性、可见性与权限；不能只靠路由或按钮隐藏。
- 导出只接收已经归一化的查询或选中 ID；服务端式 adapter 再执行相同数据范围和字段遮蔽，不信任前端列配置。
- 模拟打印必须先打开预览，用户确认后才提交一次打印命令；取消预览没有写入。计数、操作日志和结果必须原子提交，规则由 `DEC-ORD-012` 决定。
- 详情中的修改开票信息、添加备注、添加附件、新增、修改、复制、退回、删除、作废、分享、收款、出库和发货均不是本切片表单，不得提前保存半成品数据。

只读聚合最小模型如下；字段名称是领域契约，不要求 UI 原样显示英文：

| 聚合部分 | 必需字段 | 约束 |
|---|---|---|
| 订单头 | `id, orderNo, status, orderedAt, createdAt, updatedAt` | `id/orderNo` 企业内唯一；时间为 ISO 字符串并由受控时钟解释 |
| 人员快照 | `salespersonSnapshot{id,name}, creatorSnapshot{id,name}` | 保留当时显示名，不反向编辑组织资料 |
| 客户快照 | `customerSnapshot{id,code,name,categoryId}`、`settlementCustomerSnapshot{id,code,name}`、`settlementSnapshot{method,creditTermDays}` | 来源 ID + 下单快照；结算客户关系见 `DEC-ORD-008` |
| 收货快照 | `shippingSnapshot{recipient,phone,province,city,district,address,deliveryMethod}`、`requestedDeliveryAt` | 收货字段是订单历史事实；电话/地址按角色遮蔽 |
| 仓库/履约投影 | `fulfillmentWarehouseSnapshot{id,code,name}`、`outboundPrintCount, logisticsCodes, hasDifference` | 只读历史/投影；`ORD-001` 不计算或推进履约 |

| 发票快照 | `invoiceStatus, invoiceType, invoiceTitleSnapshot?` | 只读；修改归 `ORD-002` 或后续明确切片 |
| 商品行 | `id, sequence, spuId, skuId, productCodeSnapshot, productNameSnapshot, skuCodeSnapshot, specificationSnapshot, imageSnapshot?, unitSnapshot, quantity, discountBasisPoints, originalUnitPriceCents, dealUnitPriceCents, subtotalCents, weightSubtotalGrams?, reason?` | 行序号稳定；数量/单位沿用商品已确认精度；价格不重新解析 |

### 详情与操作矩阵

基础信息必须显示状态、客户、单号、客户编码、结算方式、业务员、制单人和下单时间。应收额度读取客户当前 provider；应收总额和可用预收读取资金 provider；本单占用预收受 `DEC-ORD-004` 约束。不得从订单金额反推；未实现显示“数据源尚未接入”，失败显示“加载失败”并允许单区块重试，不能显示 0。

订单详情 Tab 按下列分区展示：

1. 商品明细：序号、商品图片/名称/编码、规格、数量、单位、折扣、成交单价/原价、金额小计、重量小计和原因；“库荐”整列明确显示算法未接入，不从库存猜算；规格 1/2/3 不展示且不建字段。
2. 金额汇总：原价金额、商品优惠（含赠品）、整单优惠、运费和订单金额；遮蔽权限与列表一致。
3. 收货信息：交货日期、配送方式、收货人/电话、详细地址和发货仓库。
4. 开票信息：不开票/待开票/已开票及现有抬头快照；本切片只读。
5. 自定义属性：显示下单时保存的定义和值快照；不根据不存在的设置配置生成字段。
6. 备注、附件和操作日志：只读展示已有资料；系统日志详情不在本切片伪造。

### 状态与计算

- 本切片只展示状态，不提供任何状态迁移命令。状态枚举必须由 service/config 单点拥有，列表、详情、筛选和时间轴复用同一映射。
- 规范状态仅八个：`pending-order-review`（待订单审核）、`pending-finance-review`（待财务审核）、`approved`（已审核/待出库）、`outbound-in-progress`（出库中）、`outbound`（已出库/待发货）、`shipped`（已发货/待签收）、`completed`（已完成）、`canceled`（已取消）。别名只用于中文提示，不建立重复枚举。
- 详情四段时间轴为只读投影：审核、出库、发货、完成；当前状态映射到阶段，取消状态单独显示终止原因/时间（若快照存在）。不得用时间轴点击推进状态。
- 金额全部使用整数分：`orderAmountCents = originalAmountCents + productDiscountCents + orderDiscountCents + freightCents`。两类优惠必须小于等于 0，运费大于等于 0；不满足等式的订单 Schema 拒绝载入，不能在 UI 静默修正。
- 行小计是保存的成交快照并以整数分显示；`ORD-001` 不重新执行价格、授权、促销或单位换算。折扣显示值来自 `discountBasisPoints`，`10000` 表示 100%。
- 打印次数是非负整数；只有确认打印命令成功才增加。出库打印、差异标记和物流编码是只读履约投影，当前切片不计算。
- 订单、列表结果、导出和打印均遵守企业隔离、软删除和角色可见性；不存在或不可见的订单对外统一为未找到，避免泄露 ID。

| `couponSelection` | 优惠券 | 引用/null | 否 | 空 | provider 未接入时 unavailable；不得手输虚假券 |
| `manualOrderDiscountCents` | 整单优惠 | 非负金额输入 | 否 | 0 | 存储为负值；权限、上限和与券合并规则见 `DEC-ORD-021` |
| `freightCents` | 运费 | 非负金额 | 否 | 0 | 两位小数转整数分 |
| `orderAmountCents` | 订单金额 | 整数分 | — | 计算只读 | 完整等式和不小于 0 规则见 `DEC-ORD-021` |
| `requestedDeliveryAt` | 交货时间 | datetime | 是 | 受控当前分钟 | 时区和过去时间处理见 `DEC-ORD-022` |
| `deliveryMethod` | 配送方式 | enum | 是 | 空 | 送货上门/物流配送/客户自提，禁止默选未确认方式 |
| 收货快照 | 地址、收货人、电话、省市区、详细地址 | string | 是 | 客户当前默认地址 | 弹窗只改订单副本，复制使用本地 clipboard adapter，见 `DEC-ORD-022` |
| `invoiceTitleSnapshot` | 发票抬头 | string/null | 条件必填 | 客户抬头或名称 | 不开发票时清空；不增加原文未列的专票银行字段 |
| `customAttributes` | 产品类型、开单日期、补录之前时间 | 快照数组 | 否 | 空 | 当前只支持 `DEC-ORD-011` 已确认三项；设置 provider 未接入时不生成更多字段 |
| `remark` | 备注 | string/null | 否 | 空 | 推荐去首尾空格后最多 500 字，见 `DEC-ORD-023` |
| `attachments` | 附件 | fake metadata[] | 否 | 空数组 | 类型、大小、数量及失败语义见 `DEC-ORD-023` |

提交必须先完成字段级校验，再由 Service 在同一业务事务中重新校验客户、分类起订额、信用、预收、SKU 状态、授权、价格、单位、仓库、权限、版本和金额等式。任何失败都不得分配可见订单号、保存部分订单、占用部分预收或留下半条日志。

### 状态与计算

- `DEC-ORD-014` 推荐：新单在成功事务内按企业和 `Asia/Shanghai` 自然日生成 `CA-YYMMDD-#####`；日序列从 00001 递增，失败不消耗，对已成功/取消/标记删除订单不复用，编辑永不改变。
- `DEC-ORD-015` 推荐：无持久草稿；首次保存状态固定 `pending-order-review`。保存回详情，F7 成功后重置，F8 在 `ORD-003/004` 和资金编排未完成前禁用并显示原因，不能绕过审核。
- `DEC-ORD-016` 推荐：只有 `pending-order-review` 可直接修改；`pending-finance-review` 必须先由 `ORD-003` 退回，已审核及以后只读。修改保留身份字段，用 `expectedUpdatedAt` 做乐观并发检查并整体替换快照。
- `DEC-ORD-017` 推荐：仅启用客户可代下单；`canSelfOrder` 只约束移动自主下单。业务员默认当前操作者对应员工且允许切换；改变客户需确认并清空商品、模板来源、优惠、收货/发票和财务预览后重新解析。客户、资金或信用必需 provider 不可用时阻止保存。
- `DEC-ORD-018` 推荐：发货仓库不使用“全部”默认值，必须显式选择启用且非禁售仓库；虚拟/实体不额外排除。保存时再次校验，仓库变为禁售/禁用则拒绝。
- `DEC-ORD-019` 推荐：订单以 SKU 为选品粒度，基本单位默认；数量为所选单位正整数，换算后须满足基本单位起订量与倍数。同一 SKU+单位只保留一行，重复添加累加；不同单位可分行。换单位保留基本单位总量，无法整除成正整数时要求用户重新填写，不静默取整。
- `DEC-PRD-001` 推荐：先由 `PRD-002` 解析客户价 > 等级价 > 基准价；再依次应用客户分类折扣、会员折扣、单一商品促销、优惠券，逐阶段四舍五入到分并保存来源/优惠明细；人工行价/折扣在自动商品优惠后覆盖，最后应用整单优惠和运费。未实现的会员/促销/优惠券 provider 显示 unavailable 且该阶段不参与，不能伪装为“无可用优惠”。
- `DEC-ORD-020` 推荐：成交单价是保存权威值；改折扣按原价算成交价并到分，改成交价反算仅供显示的折扣。手工改价需权限；低于最低或高于最高售价必须同时标记特价，后续由 `DEC-ORD-003` 审批。赠品要求独立权限，成交价/小计为 0、折扣显示 0%，原价全额计入商品优惠，但仍需商品可订。
- `DEC-ORD-021` 推荐：金额全用整数分；`lineSubtotal=quantity×dealUnitPrice`，`originalAmount=Σ(quantity×originalUnitPrice)`，`productDiscount=Σ(lineSubtotal-lineOriginal)`，`orderDiscount=-(couponDiscount+manualOrderDiscount)`，`orderAmount=originalAmount+productDiscount+orderDiscount+freight`。手工整单优惠不超过扣券后的商品小计，最终金额不得为负；数量合计按页面输入数量数值求和并同时显示行数，重量按基本单位克数换算汇总。
- `DEC-ORD-022` 推荐：交货时间使用企业时区、默认当前分钟；新增不得早于当前分钟，编辑保留旧过去值但一旦修改须不早于当前。三种配送都保存完整客户地址快照；地址弹窗不回写客户。发票非 none 时抬头必填，默认客户抬头否则客户名；当前不增加未列出的专票字段。
- `DEC-ORD-023` 推荐：备注最多 500 字；附件仅 pdf/jpg/png，单文件≤5MB、最多 10 个，原型只保存虚构元数据。选择、校验或保存失败不保留半附件，移除只影响当前可编辑订单。
- `DEC-ORD-024` 推荐：模板按 assisted-order 渠道解析并显示接收/拒绝行，使用 source key 幂等合并；粘贴格式固定 `skuCode,quantity,unitCode`（unitCode 可空取基本单位），先预览且任一错误时不允许确认；扫码以文本条码精确匹配并添加/累加；清空需确认；选择商品后焦点移到下一空行。
- `DEC-ORD-025` 推荐：超级管理员、销售主管、业务员拥有代下/修改/分享；改价和赠品作为独立权限，baseline 默认授予前三类但必须能单独关闭测试。仓库、财务无建单/修改/分享权限。路由、UI、Service、分享输出四层使用同一授权结果；原型仍是企业内全量，待 `SET-001/002` 收紧。
- `DEC-ORD-026` 推荐：分享默认 7 天，可选 1/7/30 天；同一订单重发使旧 token 立即失效，取消订单也失效。`[createdAt,expiresAt)` 内可访问；首次成功访问为已查看，确认幂等变为已确认且不推进订单状态。公开页只显示单号、客户名称、状态、商品、金额、配送方式和交货时间；电话、详细地址、信用/预收、内部 ID/日志不返回。token 使用不可预测值且日志不得明文记录；二维码只编码同一 URL。
- `DEC-ORD-027` 推荐：保存/修改携带唯一 `requestId`，相同请求只产生一个结果；提交时重新读取所有拥有者事实并以 `expectedUpdatedAt` 拒绝并发覆盖。客户、授权、价格、仓库、资金属于保存必需 provider，失败整体回滚；库荐、动态属性扩展以及未选择的营销能力可局部 unavailable。错误必须定位到字段/行或 provider，保留用户输入并允许安全重试。
- `DEC-ORD-002` 推荐：建单和审核均不预占、不扣减库存，也不因当前库存不足阻止保存；只校验仓库可销售并展示库存/库荐 unavailable。`ORD-004` 确认出库时再做 FIFO、不足检查和真实扣减。
- `DEC-ORD-004` 推荐：保存时自动占用 `min(当前可用预收,订单金额)`，用户不可改；剩余新增应收=`订单金额-占用预收`，信用额度为 null/0 时不限制，正额度下 `当前应收+剩余新增应收` 超限则拒绝。修改以同一订单旧占用为基准原子增占/释放差额；失败回滚订单。退回不释放，取消/删除/作废未履约订单释放；后续确认收款时转核销，退款不自动恢复预收。普通 Mock 场景提供确定性 fake 资金 command，unavailable/error 场景必须阻止保存。

上述内容是等待产品负责人确认的推荐方案，不因写入本规格而自动成为已决定事实。用户确认后必须逐项把对应 `DEC-*` 改为 `decided`，删除“推荐/待确认”语气并把本切片提升为 `ready`。

### 页面状态与 Mock

| 场景 | 表单/分享必须表现 | 保存与恢复 |
|---|---|---|
| `normal` | 启用客户、可订/不可订 SKU、两个单位、有效模板、可售/禁售仓、可用预收和已保存可分享订单 | 新增、修改、F7、模板、扫码、分享均可重复 |
| `empty` | 无客户/仓库/商品/模板分别给所属空状态；表单不造默认主数据 | 缺少必需候选时保存不可用；模板为空不影响手工选品 |
| `error` | 订单加载/保存/分享主请求失败保留输入并可重试 | Repository、单号、预收占用和日志均不产生半结果 |
| `slow` | 候选、价格、提交和分享使用受控延迟；显示局部 loading | 保存按钮/F7/F8禁重复；旧候选请求不得覆盖新客户结果 |
| `permission-denied` | 路由拒绝无建单角色；细权限关闭后对应控件只读/不显示 | 直接 Service 调用同样拒绝，切换允许权限后可重进 |
| `partial-failure` | 库荐/设置扩展/未接入营销能力局部 unavailable；必需 provider 失败明确阻断保存 | 恢复 provider 后不清空输入，重新校验后可提交 |
| `boundary` | 金额 0/上限、折扣 0/100、单位不可整除、重复 SKU、最低/最高价、交货时间、5MB/10个附件、分享过期端点 | 可重复验证，任一失败保持事务前哈希 |
| `concurrent` | 两个编辑会话使用同一旧版本 | 首个成功，第二个显示冲突并要求重新加载，不静默覆盖 |

- 唯一 baseline 在现有订单 fixture 上扩展：至少两个启用客户（不同信用/预收）、一个不可下单客户、可售/禁售仓、授权/未授权/下架 SKU、价格上下限、模板接收/拒绝行、一个待订单审核可编辑订单和分享未查看/已查看/已确认/过期记录。资金数据必须标记为 `ORD-002` 的确定性 fake adapter，不声称 `FIN-001` 已完成。
- baseline/work 继续原子重置并校验哈希；固定 clock 与企业时区驱动订单号日期、调价生效、分享过期和交货时间。测试不得直接修改 fixture 绕过 Service。
- fake 文件、clipboard、扫码、二维码和分享 URL 不访问真实文件服务、摄像头、短链、短信或公网；页面必须明确原型性质。公开分享页做独立输出白名单和 token 校验。
