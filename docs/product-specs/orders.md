# 订单领域规格

## 需求来源与事实边界

- 直接业务来源：[02-订单模块.md](../references/requirements/02-订单模块.md)；全局交互与角色资料来自 [01-整体架构与首页.md](../references/requirements/01-整体架构与首页.md) §4～§5。
- 功能切片、原文章节、依赖、规则归属和字段准备度以 [产品规格索引](index.md) 为唯一目录。
- `ORD-01～ORD-15` 直接整理自原文 §8。分层、整数分、原子提交、Mock 场景属于 Harness 工程约束，不表示原文已定义技术实现。
- 对应切片为 `source-only` 时只能提取契约；订单标签、库存预占、特价审批、预收占用、应收时点和退款跨域结果按索引中的人工决策门处理。

## 目标与范围

覆盖客户订单、客户退单、差异单、销售出库单、订单/销售统计。原型 P0 黄金旅程是“新增订单 → 审核 → 部分/全部出库 → 应收与收款记录”。

## 主要页面

- 订单：列表、筛选/批量操作、新增、详情、分享。
- 退单：列表、新增、详情与退款状态。
- 差异单：列表与详情。
- 销售出库：列表、详情、作废后重新出库。
- 统计：商品明细/汇总、客户汇总、出入库明细/汇总。

## 核心状态

正常销售状态单向推进；需求明确允许的例外仅为“待财务审核 → 待订单审核”。实现时状态枚举、允许动作和操作者权限必须位于 service/config，不散落在按钮判断中。

## 业务规则

| ID | 必须行为 |
|---|---|
| ORD-01 | 单号按“前缀 + YYMMDD + 序号”自动生成且不可编辑。 |
| ORD-02 | 正常状态不可回退；仅允许待财务审核回到待订单审核。 |
| ORD-03 | 实出小于应出时自动生成关联差异单。 |
| ORD-04 | 整单退和部分退均关联原订单。 |
| ORD-05 | 可退数量不得超过已出库数量。 |
| ORD-06 | 退款必须经过确认退款流程。 |
| ORD-07 | 确认出库时实时扣减可用库存。 |
| ORD-08 | 选择客户与商品后自动匹配客户等级价格。 |
| ORD-09 | 客户只能订购已授权商品。 |
| ORD-10 | 分享链接超过有效期后不可查看或确认。 |
| ORD-11 | 下单时自动占用客户预收金额。 |
| ORD-12 | 特价订单必须标记并进入特殊审批。 |
| ORD-13 | 作废出库单保留可查，并支持重新出库。 |
| ORD-14 | 订单自定义属性来源于设置配置。 |
| ORD-15 | 统计二维表支持配置展示维度。 |

## 跨领域约束

- 下单读取客户状态、商品授权和价格；任何校验失败都不能生成半成品订单。
- 确认出库与库存扣减是一个业务结果；失败时两者都不生效。
- 出库/签收形成应收的具体时点需按资金规格；未确认前不得自行决定。
- 原始需求没有库存预占规则；不得因为系统通常会预占库存而自行实现。
- `ORD-11` 没有给出预收占用金额和释放规则；`DEC-ORD-004` 决定前不得用“占满可用余额”等默认算法。
- 金额使用整数分，优惠、运费、预收占用和应收之间必须有可追溯明细。

## 实现映射

`src/features/orders/` 保存订单类型、repository、状态机 service、stores 和页面；库存、商品、客户、资金能力通过公开 provider 注入。

## P0 验收

1. 按客户、日期、单号、状态筛选订单，列表/分页/空结果正确。
2. 已授权商品带入正确价格优先级，未授权商品不可提交且说明原因。
3. 新订单单号不可修改，金额汇总以分计算并正确格式化。
4. 状态按允许路径推进；非法回退被 service 拒绝而非仅隐藏按钮。
5. 部分出库同时扣正确库存并生成差异单；库存不足整体失败。
6. 退货数量超过已出库数量被拒绝；退款需确认。
7. normal/error/slow/permission-denied 场景和订单黄金旅程测试通过。

## 原型模拟边界

分享、打印、导入导出、物流与收款通道只模拟结果。统计先用固定数据验证信息结构，未定义的指标口径不得声称真实准确。

### 表单与校验

`ORD-001` 没有新增/修改业务表单，只有查询、导出和模拟打印输入：

- 查询 Schema 对页码、枚举、日期顺序和金额顺序做运行时校验；金额文本按两位小数安全转整数分，不接受 `NaN`、负数或超出安全整数范围。
- `orderId`、选择集合和打印目标必须在 service 中重新校验存在性、可见性与权限；不能只靠路由或按钮隐藏。
- 导出只接收已经归一化的查询或选中 ID；服务端式 adapter 再执行相同数据范围和字段遮蔽，不信任前端列配置。
- 模拟打印必须先打开预览，用户确认后才提交一次打印命令；取消预览没有写入。计数、操作日志和结果必须原子提交，规则由 `DEC-ORD-012` 决定。
- 详情中的修改开票信息、添加备注、添加附件、新增、修改、复制、退回、删除、作废、分享、收款、出库和发货均不是本切片表单，不得提前保存半成品数据。

只读聚合最小模型如下；字段名称是领域契约，不要求 UI 原样显示英文：

| 聚合部分 | 必需字段 | 约束 |
|---|---|---|
| 订单头 | `id, orderNo, status, orderedAt, createdAt, updatedAt` | `id/orderNo` 企业内唯一；时间为 ISO 字符串并由受控时钟解释 |
| 人员快照 | `salespersonSnapshot{id,name}, creatorSnapshot{id,name}` | 保留当时显示名，不反向编辑组织资料 |
| 客户快照 | `customerSnapshot{id,code,name,categoryId}`、`settlementCustomerSnapshot{id,code,name}`、`settlementSnapshot{method,creditTermDays}` | 来源 ID + 下单快照；结算客户关系见 `DEC-ORD-008` |
| 收货快照 | `shippingSnapshot{recipient,phone,province,city,district,address,deliveryMethod}`、`requestedDeliveryAt` | 收货字段是订单历史事实；电话/地址按角色遮蔽 |
| 仓库/履约投影 | `fulfillmentWarehouseSnapshot{id,code,name}`、`outboundPrintCount, logisticsCodes, hasDifference` | 只读历史/投影；`ORD-001` 不计算或推进履约 |
| 金额快照 | `originalAmountCents, productDiscountCents, orderDiscountCents, freightCents, orderAmountCents` | 优惠保存为 0 或负整数分；总额等式见“状态与计算” |
| 发票快照 | `invoiceStatus, invoiceType, invoiceTitleSnapshot?` | 只读；修改归 `ORD-002` 或后续明确切片 |
| 商品行 | `id, sequence, spuId, skuId, productCodeSnapshot, productNameSnapshot, skuCodeSnapshot, specificationSnapshot, imageSnapshot?, unitSnapshot, quantity, discountBasisPoints, originalUnitPriceCents, dealUnitPriceCents, subtotalCents, weightSubtotalGrams?, reason?` | 行序号稳定；数量/单位沿用商品已确认精度；价格不重新解析 |
| 自定义属性 | `customAttributes[]` | 历史定义和值快照，见 `DEC-ORD-011` |
| 附属只读资料 | `remark?, attachments[], activityLogs[]` | 附件只存模拟元数据；日志最少含动作、操作者快照、时间和摘要 |

### 详情与操作矩阵

基础信息必须显示状态、客户、单号、客户编码、结算方式、业务员、制单人和下单时间。应收额度、应收总额、可用预收、订单占用预收属于实时/跨域数据；不得从订单金额反推，provider 失败表现由 `DEC-ORD-009` 决定。

订单详情 Tab 按下列分区展示：

1. 商品明细：序号、商品图片/名称/编码、规格、数量、单位、折扣、成交单价/原价、金额小计、重量小计和原因；“库荐”及规格 1/2/3 按 `DEC-ORD-009/011` 处理。
2. 金额汇总：原价金额、商品优惠（含赠品）、整单优惠、运费和订单金额；遮蔽权限与列表一致。
3. 收货信息：交货日期、配送方式、收货人/电话、详细地址和发货仓库。
4. 开票信息：不开票/待开票/已开票及现有抬头快照；本切片只读。
5. 自定义属性：显示下单时保存的定义和值快照；不根据不存在的设置配置生成字段。
6. 备注、附件和操作日志：只读展示已有资料；系统日志详情不在本切片伪造。

出库发货记录、签收记录和收款记录 Tab 必须存在，但在所属切片/provider 未实现时显示“数据源尚未接入”及所属能力，不显示空表、0 元或“暂无数据”来暗示查询成功。精确边界由 `DEC-ORD-010` 决定。

### 状态与计算

- 本切片只展示状态，不提供任何状态迁移命令。状态枚举必须由 service/config 单点拥有，列表、详情、筛选和时间轴复用同一映射。
- 原文 §2.1 同时列“已审核/待出库”，§2.3 又将它们描述为同一节点；规范化枚举和中文标签由 `DEC-ORD-005` 决定。
- 详情四段时间轴为只读投影：审核、出库、发货、完成；当前状态映射到阶段，取消状态单独显示终止原因/时间（若快照存在）。不得用时间轴点击推进状态。
- 金额全部使用整数分：`orderAmountCents = originalAmountCents + productDiscountCents + orderDiscountCents + freightCents`。两类优惠必须小于等于 0，运费大于等于 0；不满足等式的订单 Schema 拒绝载入，不能在 UI 静默修正。
- 行小计是保存的成交快照并以整数分显示；`ORD-001` 不重新执行价格、授权、促销或单位换算。折扣显示值来自 `discountBasisPoints`，`10000` 表示 100%。
- 打印次数是非负整数；只有确认打印命令成功才增加。出库打印、差异标记和物流编码是只读履约投影，当前切片不计算。
- 订单、列表结果、导出和打印均遵守企业隔离、软删除和角色可见性；不存在或不可见的订单对外统一为未找到，避免泄露 ID。

### 页面状态与 Mock

单一订单 baseline 至少覆盖：每个确认状态一条、下单客户与结算客户相同/不同、三种结算方式、三种配送方式、多个仓库、金额和日期边界、打印次数 0/非 0、物流编码空/多值、差异是/否、无图片/无附件/无备注，以及至少 31 条记录验证默认分页。所有姓名、电话、地址和单号均为明显虚构数据。

| 场景 | 列表 | 详情/跨域卡片 | 可恢复性 |
|---|---|---|---|
| `normal` | baseline 查询、筛选、分页、导出/打印正常 | 订单自身快照可见；未实现 provider 明确不可用 | 刷新保持 URL 查询 |
| `empty` | 成功返回 0 条和清空筛选入口 | 直接访问有效 fixture 仍可查看 | 清空筛选恢复 normal 查询 |
| `error` | 订单主查询失败，保留条件并显示重试 | 订单主详情失败，不渲染陈旧数据 | 重试重新调用 repository |
| `slow` | 受控延迟与 loading；旧请求不能覆盖新查询 | 骨架屏后显示结果 | 切换查询可取消/忽略旧响应 |
| `permission-denied` | 路由守卫拒绝并提供返回首页 | service 同样拒绝直接调用 | 切换允许角色后可重进 |
| `partial-failure` | 订单主列表成功；分类/业务员候选失败的筛选单独不可用 | 应收/预收/库荐或外部 Tab 失败只影响对应区块 | 单区块重试，不清空订单快照 |

- baseline 与 work 数据分离；`npm run mock:reset` 原子复制并校验哈希，干净重启得到同一结果。
- 固定模拟当前时刻与 `Asia/Shanghai` 时区；日期默认、状态展示、排序和打印日志可重复。
- 导出、打印和教程只能使用本地 fake adapter；不访问真实打印机、文件服务、物流、支付或外部视频。
- Repository 写操作仅限已确认的模拟打印事务；测试不得绕过 service 直接修改 fixture。
