# 客户领域规格

## 需求来源与事实边界

- 直接业务来源：[06-客户模块.md](../references/requirements/06-客户模块.md)；全局交互与角色资料来自 [01-整体架构与首页.md](../references/requirements/01-整体架构与首页.md) §4～§5。
- 功能切片、章节、依赖、规则归属和字段准备度以 [产品规格索引](index.md) 为唯一目录。
- `CUS-01～CUS-12` 直接整理自原文 §9。敏感字段遮蔽、跨领域 Provider、可控时钟和 fake adapter 属于 Harness 工程约束。
- 原文列出的客户状态在列表与详情间不完全一致，且未定义其合法转换和对下单的完整影响；客户编码自动生成也没有格式。相关行为按 `DEC-CUS-001`、`DEC-CUS-003` 处理。价格组合按 `DEC-PRD-001` 处理。

## 目标与范围

维护客户主数据、关系经营、会员营销与订货侧配置，为商品授权、价格、订单和应收提供客户事实。

## 主要页面

- 客户列表、详情、多区表单，商机、常购商品、分类、标签、会员等级、地图、公海。
- 外勤任务、拜访统计/明细/线路/计划。
- 优惠券、促销、发券、获客文章与积分。
- 企微运营、商城客户/员工/装修/活动/设置。
- 营销分析及拉新提成。

原型 P0 聚焦客户档案、分类/等级、标签、公海与订单所需设置；地图、企微、商城装修和 AI 分析只做低保真入口或后续阶段。

## 业务规则

| ID | 必须行为 |
|---|---|
| CUS-01 | 同一企业内客户编码唯一。 |
| CUS-02 | 达到未下单/未拜访天数后自动回收到公海。 |
| CUS-03 | 业务员每日/月领取公海客户数量受限。 |
| CUS-04 | 拜访需 GPS 签到并记录位置。 |
| CUS-05 | 优惠券支持满减、折扣、直减、免运费四种类型。 |
| CUS-06 | 优惠券按每人限领数量控制。 |
| CUS-07 | 同一商品不可同时参加多个促销。 |
| CUS-08 | 积分获取受每日和每单上限控制。 |
| CUS-09 | AI 建议标签经人工确认后才生效。 |
| CUS-10 | 客户分类折扣在下单时自动应用。 |
| CUS-11 | 达到条件后会员等级可自动或手动升级。 |
| CUS-12 | 客户地址可在地图可视化展示。 |

## 跨领域约束

客户详情中的订单、应收与价格只通过对应领域只读 provider 获取。订单可用性同时受客户状态、商品授权、价格与信用/预收规则影响，不得只检查其中一项。

## P0 验收

1. 重复客户编码无法保存；自动编码按企业内 `CUS-000001` 全局递增且不复用；四种状态统一展示，只有启用客户可下单，正信用额度超限时阻止下单。
2. 客户详情展示基本、联系、财务、标签和业务设置，敏感字段按权限遮蔽。
3. 客户分类可以维护折扣率；按已确认 `DEC-PRD-001`，订单先解析客户价 > 等级价 > 基准价，再应用分类折扣，之后依次处理会员折扣、单一商品促销、优惠券、人工行价和整单优惠。
4. 使用可控时钟触发公海回收；领取超过日/月限额时拒绝并说明剩余额度。
5. AI 标签在人工确认前不影响有效标签。
6. permission-denied/error/empty 场景均可复现。

## 原型模拟边界

GPS、地图、企微同步、消息、文章传播、商城支付和 AI 标签只模拟输入输出，不请求真实服务。模拟位置必须明确标记。

#### 2026-08-11 已确认产品决定

- `DEC-CUS-001`：后台新增客户默认启用，自助注册客户初始为待审核；只有启用客户可下单。停用客户可恢复启用；冻结必须填写原因。信用额度为 0 时不限额，正额度超限时阻止下单。
- `DEC-CUS-003`：自动编码是企业内全局递增的 `CUS-000001`，删除后不复用；允许手工编码，冲突时拒绝保存；Mock 重置恢复基准 fixture 对应的下一序号。
- `DEC-CUS-004`：§2.1.3 是客户模块二级导航，不是详情 Tab。详情按客户表单分组只读展示，顶部放编辑与状态操作，右侧放状态和变更日志；跨域指标未接入时显示不可用。
- `DEC-CUS-005`：分类树层级不限但禁止循环；停用分类不能新分配，已有客户关系保留；存在子分类或客户引用时禁止删除；默认信用额度和账期仅在新建客户选择分类时带入，分类以后修改不追溯覆盖。
- `DEC-CUS-006`：原型只允许五种预设标签颜色；停用标签不能新分配，已有关系保留；被客户或待处理 AI 建议引用时禁止删除；标签被使用后类型不可改；多标签筛选按任一标签命中。
- `DEC-CUS-007`：fake AI 只生成待确认建议，允许逐条或批量确认/拒绝，确认后才新增或移除客户标签；客户数按选择范围自动计算且最多 1000。本切片实现立即分析，定时分析显示“规划中”。
- `DEC-CUS-008`：允许查看库存、允许自主下单、允许查看价格、接收营销消息、自动分配订单五项默认关闭；业务员手工选择；原型不执行自动分配，开启时提示规则未配置。
- `DEC-CUS-009`：超级管理员可完整查看和编辑；销售主管、业务员可查看电话，但银行账号和税号遮蔽且不可导出；仓库、财务按全局矩阵不能进入客户模块；导出遵循相同可见范围。
- `DEC-CUS-010`：原文“清空页览”按“清空表单”实现，有脏数据时二次确认；保存成功返回列表，保存并新增成功后打开空白新增表单；视频教程只显示原型模拟说明。
- `DEC-CUS-011`：本切片只实现法人代表、注册资本、成立日期、经营范围、店铺面积、员工人数六个预置字段；不提供动态新增字段入口，动态字段另拆后续切片。
- `DEC-CUS-012`：客户分类和业务员新增初始为空且必须手工选择；结算方式默认现结，切换为现结/月结时清空账期天数；分类与标签默认启用，标签默认手动标签和蓝色；分类筛选包含所选分类全部后代；待审核、启用、停用、冻结客户均可编辑资料，但状态操作仍受确认状态机限制。

- `DEC-CUS-013`：新建客户选择存在默认账期的分类时，自动把结算方式切换为账期结算并带入天数；用户之后手工切换为现结或月结时清空账期天数。没有默认账期的分类不改变当前结算方式。

### 状态与计算

- 客户分类、A/B/C 客户级别和后续会员等级是三个独立概念：`categoryId`、`importanceLevel`、未来 `memberLevelId`。列表“客户分类”显示分类树名称，不用会员等级替换。
- 客户状态统一为待审核、启用、停用、冻结。后台新增默认启用，自助注册默认待审核；启用可停用或冻结，停用可恢复启用，冻结可解冻为启用且冻结原因必填。当前没有来源支持删除或把停用直接改为冻结，未列转换不得实现。
- 只有启用客户可下单。`creditLimitCents=0` 表示不限制；正额度在订单领域以届时已确认的应收/订单口径校验，超过额度时必须阻止下单。客户页面只维护额度，不伪造可用额度。
- 分类折扣率是原价百分比，范围 1～100，默认 100；`CUS-001` 只维护该值，订单按已确认 `DEC-PRD-001` 在预营销价格之后应用分类折扣并逐阶段四舍五入到分。
- 分类起订金额和信用额度使用整数分；展示格式化不改变原始值。分类默认信用额度/账期在新建客户选择分类时带入，之后修改分类不追溯已有客户。
- 标签颜色保存预设真实色值并同时显示文字名称；状态不能只靠颜色表达。停用后不可新关联、已有关系保留；存在客户或待处理建议引用时不可删除；被使用后类型不可改。
- AI 建议与有效标签分开存储。fake AI 只能产生 suggestion；逐条或批量确认后才改变客户 `tagIds`，拒绝只结束建议。当前只实现立即分析，定时分析明确标记规划中。
- 自动客户编码按企业内 `CUS-000001` 全局递增且永不复用；手工编码允许使用，但 repository/service 必须以 `CUS-01` 拒绝冲突。
- 五个业务设置默认 false；`autoAssignOrders=true` 在本原型只提示规则未配置，不产生自动分配副作用。
- 超级管理员可完整查看编辑；销售主管和业务员可见电话，银行账号和税号遮蔽且不可导出；仓库和财务不能进入客户模块。
- 本切片只保存六个预置属性，不实现动态自定义字段入口。
- 列表累计订单数、累计消费金额、当前欠款来自未来领域 provider。Provider 未接入时用明确 unavailable 状态，不以 0 或虚构 fixture 冒充真实业务结果。
