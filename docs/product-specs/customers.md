# 客户领域规格

## 需求来源与事实边界

- 直接业务来源：[06-客户模块.md](../references/requirements/06-客户模块.md)；全局交互与角色资料来自 [01-整体架构与首页.md](../references/requirements/01-整体架构与首页.md) §4～§5。
- 功能切片、章节、依赖、规则归属和字段准备度以 [产品规格索引](index.md) 为唯一目录。
- `CUS-01～CUS-12` 直接整理自原文 §9。敏感字段遮蔽、跨领域 Provider、可控时钟和 fake adapter 属于 Harness 工程约束。
- 原文列出的客户状态在列表与详情间不完全一致，且未定义其合法转换和对下单的完整影响；客户编码自动生成也没有格式。相关行为按 `DEC-CUS-001`、`DEC-CUS-003` 处理。价格组合按 `DEC-PRD-001` 处理。

## 目标与范围

维护客户主数据、关系经营、会员营销与订货侧配置，为商品授权、价格、订单和应收提供客户事实。

## 主要页面

- 客户列表、详情、多区表单，商机、常购商品、分类、标签、会员等级、地图、公海。
- 外勤任务、拜访统计/明细/线路/计划。
- 优惠券、促销、发券、获客文章与积分。
- 企微运营、商城客户/员工/装修/活动/设置。
- 营销分析及拉新提成。

原型 P0 聚焦客户档案、分类/等级、标签、公海与订单所需设置；地图、企微、商城装修和 AI 分析只做低保真入口或后续阶段。

## 业务规则

| ID | 必须行为 |
|---|---|
| CUS-01 | 同一企业内客户编码唯一。 |
| CUS-02 | 达到未下单/未拜访天数后自动回收到公海。 |
| CUS-03 | 业务员每日/月领取公海客户数量受限。 |
| CUS-04 | 拜访需 GPS 签到并记录位置。 |
| CUS-05 | 优惠券支持满减、折扣、直减、免运费四种类型。 |
| CUS-06 | 优惠券按每人限领数量控制。 |
| CUS-07 | 同一商品不可同时参加多个促销。 |
| CUS-08 | 积分获取受每日和每单上限控制。 |
| CUS-09 | AI 建议标签经人工确认后才生效。 |
| CUS-10 | 客户分类折扣在下单时自动应用。 |
| CUS-11 | 达到条件后会员等级可自动或手动升级。 |
| CUS-12 | 客户地址可在地图可视化展示。 |

## 跨领域约束

客户详情中的订单、应收与价格只通过对应领域只读 provider 获取。订单可用性同时受客户状态、商品授权、价格与信用/预收规则影响，不得只检查其中一项。

## P0 验收

1. 重复客户编码无法保存；客户编码自动生成等待 `DEC-CUS-003`，四种状态的统一枚举、转换和下单影响等待 `DEC-CUS-001` 决定。
2. 客户详情展示基本、联系、财务、标签和业务设置，敏感字段按权限遮蔽。
3. 客户分类可以维护折扣率；其与客户价、等级价、会员折扣的组合等待 `DEC-PRD-001` 决定。
4. 使用可控时钟触发公海回收；领取超过日/月限额时拒绝并说明剩余额度。
5. AI 标签在人工确认前不影响有效标签。
6. permission-denied/error/empty 场景均可复现。

## 原型模拟边界

GPS、地图、企微同步、消息、文章传播、商城支付和 AI 标签只模拟输入输出，不请求真实服务。模拟位置必须明确标记。

### 状态与计算

- 客户分类、A/B/C 客户级别和后续会员等级是三个独立概念：`categoryId`、`importanceLevel`、未来 `memberLevelId`。列表“客户分类”显示分类树名称，不用会员等级替换。
- 客户状态候选来自原文的待审核、启用、停用、冻结；筛选/列表遗漏冻结，默认状态、合法转换、操作者、停用/冻结副作用及订单影响全部由 `DEC-CUS-001` 决定。
- `creditLimitCents=0` 明确表示不限制；正额度如何与应收、当前订单和预收共同校验由 `DEC-CUS-001` 及后续订单/资金规格决定，客户页面不自行计算“可下单”。
- 分类折扣率是原价百分比，范围 1～100，默认 100；`CUS-001` 只维护该值，`CUS-10` 的下单应用以及与其他价格叠加由 `DEC-PRD-001` 和后续价格 Service 处理。
- 分类起订金额和信用额度使用整数分；展示格式化不改变原始值。分类默认信用额度/账期如何带入客户及后续修改是否追溯，由 `DEC-CUS-005` 决定。
- 标签颜色必须保存真实色值且同时显示文字名称；状态不能只靠颜色表达。标签停用、删除、类型修改和关联关系由 `DEC-CUS-006` 决定。
- AI 建议与有效标签分开存储。fake AI 只能产生 suggestion，`CUS-09` 要求人工确认后才能改变客户 `tagIds`；确认粒度、拒绝、移除和调度由 `DEC-CUS-007` 决定。
- 客户编码生成由 `DEC-CUS-003` 决定；无论自动或手工，repository/service 必须以 `CUS-01` 拒绝同一企业重复编码。
- 五个业务设置没有默认值，见 `DEC-CUS-008`；UI 不得通过 HTML checkbox 默认 false 把未确认值伪装成业务决定。
- 电话、银行账号、税号及其他敏感字段的完整/遮蔽展示和导出权限见 `DEC-CUS-009`。
- “系统预置自定义字段，支持扩展”没有给出配置入口和动态类型；六个预置字段与动态扩展的范围由 `DEC-CUS-011` 决定。
- 列表累计订单数、累计消费金额、应收余额来自未来领域 provider。Provider 未接入时用明确 unavailable 状态，不以 0 或虚构 fixture 冒充真实业务结果。

### 页面状态与 Mock

业务 fixture 只有在本切片 ready 后才能写入 `featureData.CUS-001`，并由可执行 schema 约束。客户、分类、标签和 AI 建议分别拥有唯一实体集合；其他切片只引用 ID，不复制客户状态、名称或额度。

| 场景 | 必备数据/行为 | 页面期望 |
|---|---|---|
| normal | 至少覆盖不同分类、标签、业务员、地区和已决定状态；含一条待确认 AI 建议 | 列表、筛选、表单和确定操作可重复 |
| empty | 客户集合为空；分类/标签可独立存在 | 客户列表显示“暂无数据”和新增入口，不显示错误 |
| error | 列表或保存返回稳定错误码 | 保留筛选/表单现场，显示原因和重试，不产生半保存 |
| slow | 固定延迟 | 显示 loading，防止重复提交，完成后恢复操作 |
| permission-denied | 当前模拟角色没有客户模块权限或 command 被拒绝 | 路由、UI、service 三层拒绝，不能只隐藏按钮 |
| partial-failure | 客户主数据成功，但订单/资金统计 provider 不可用 | 主数据仍可看，三个跨域指标单独显示“数据源未接入/加载失败” |

附件、地图、视频教程、导出、定时分析和 AI 分析都使用 fake adapter，并显示“原型模拟”。Mock 姓名、电话、地址、银行账号、税号和经纬度必须明显虚构，不能使用真实个人或企业资料。
