# 产品认知

## 一句话定位

蜂订全渠道营销系统是面向 B2B 订货业务的 PC 管理后台，连接客户、商品、订单、采购、库存和资金，让销售与供应链业务形成可追踪的闭环。

当前交付是用于需求验证的前端原型，不是可上线的生产系统。

## 当前阶段目标

1. 用 Vue 3 和确定性 Mock 数据验证信息架构、页面操作与关键业务流程。
2. 让业务方能判断“功能是否符合实际工作方式”，而不被后端、第三方接入和性能工程阻塞。
3. 让后续 AI 或开发者在遇到未知问题时先查仓库事实，无法确认时显式记录缺口，不凭经验补业务规则。

## 主要角色及任务

| 角色 | 主要任务 |
|---|---|
| 运营/管理者 | 查看待办、经营指标、预警和跨模块进度 |
| 销售主管/业务员 | 建客户、维护价格与授权、建单、跟踪交付和回款 |
| 采购人员 | 分析缺货、生成采购单、跟踪入库和供应商 |
| 仓库人员 | 管库存、入出库、盘点、分拣和配送 |
| 财务人员 | 审核、应收应付、收付款、核销和结转 |
| 系统管理员 | 维护组织、账号、角色权限、基础资料和日志 |

## 必须成立的业务闭环

- 销售：客户与商品授权/价格 → 订单 → 审核 → 出库/发货 → 签收 → 应收 → 收款/核销。
- 退货：原销售订单 → 退单 → 退货入库 → 退款确认。
- 采购：库存或订单需求 → 补货建议 → 采购订单 → 入库 → 应付 → 付款/核销。
- 库存：所有库存变化必须由明确单据驱动并可追溯。

## 原型范围

本阶段优先验证：应用壳、Dashboard、订单列表/详情/建单主流程、商品与价格授权、采购入库、库存出库/盘点、客户档案、资金核销、角色权限。

以下只做可解释的模拟：导入导出、打印、消息通知、在线支付、GPS/地图、企微、AI 分析、定时任务、真实文件上传。

商家模块和独立数据分析模块只有总览名称，没有独立详细需求；在需求补齐前不得生成完整功能。

## 产品判断原则

- 优先保证状态、金额、库存与权限正确，再追求视觉效果。
- 列表页帮助用户快速筛选和批量处理；详情页解释来源、状态与后续动作。
- 高风险动作必须展示影响并二次确认；不可执行时说明原因，不只禁用按钮。
- 原型数据必须能稳定复现正常、空、异常、慢响应和权限不足场景。
- 参考产品只用于理解企业后台的信息密度和操作习惯，不复制其品牌表达。

## 不确定性与人工职责

- 原始资料没有明确字段、枚举、默认值、公式、状态、权限或副作用时，首先缩小受影响范围，不把整个模块笼统标为完成或失败。
- AI 负责查找证据、指出冲突、给出可选方案和推荐，并继续推进不受影响的规格、代码和验证。
- 产品负责人决定业务含义、流程取舍、口径、优先级和范围；财务、仓库、采购或管理员参与其专业流程的形成时点和权限决定。
- 人工决定必须写回产品规格和 active plan；只存在于聊天中的决定不能被后续任务可靠继承。
- 原型可以模拟外部服务，但不能模拟成“业务规则已经确定”。界面模拟和业务决策是两件事。

## 非目标

- 不证明生产级安全、并发、性能、审计合规或第三方通道可用性。
- 不以页面数量作为完成标准；完成以业务行为和验收证据为准。
- 不在缺少业务依据时追求“看起来完整”。
