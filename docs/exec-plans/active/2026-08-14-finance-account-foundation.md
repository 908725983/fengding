# FIN-003 资金账户、银行与结转基础

- 类型：business-feature
- 功能：FIN-003

## 目标

从原始需求提取资金账户、账户流水与汇总、月度资金结转、银行资料和在线支付设置的可编码契约，明确余额所有权、期间锁定、账户/银行生命周期、权限和原型模拟边界。先把会影响资金结果的缺口登记为人工决策；在 `FIN-003` 达到 `ready` 前不创建资金业务代码、页面或 fixture。

## 范围与非目标

本切片只覆盖 `FIN-003`：资金账户列表/详情、只读账户收支明细与汇总、账户新增/编辑/停用、银行列表与维护、月度结转/反结转基础、未来资金动作使用的账户余额与结转公开门，以及在线支付通道的明确模拟入口。

客户应收、收款与核销属于 `FIN-001`；供应商应付与付款属于 `FIN-002`；退款、转账、其他收支属于 `FIN-004`；机构收款和资金统计属于 `FIN-005`。本切片不提前生成这些单据或伪造真实支付开通、银行余额同步、收付款成功和核销结果。原文把“其他收付款明细/汇总”放在资金账户导航下，但其事实来自后续其他收支单据，本切片只声明等待 `FIN-004`，不造空壳成功数据。

## 验证路径

- specification：逐项核对原文 §5.1～§5.8、FIN-03/06/09、全局页面规范与资金细权限，形成页面/字段、实体、计算、期间锁定、权限、Mock 和验收矩阵；运行 `npm run verify:harness` 与 `git diff --check`。
- implementation：按 `Types → Schema → Repository → Service → Runtime/Store → UI` 分段；账户余额、不可变流水、期间快照和结转门由资金领域拥有，未来切片只能走 `public.ts`。
- 自动验证：金额整数分、余额公式、停用边界、幂等、乐观锁、结转整体事务、锁定月份、反结转限制、账号遮蔽、权限绕过、provider unavailable 与 reset 哈希。
- 页面状态：normal、empty、error、slow、permission-denied、partial-failure、boundary、concurrent；任何 unavailable/error 不得显示虚构 0 或支付成功。
- 人工黄金旅程：重置 → 新建/查看账户 → 核对期间汇总和逐笔余额 → 停用/恢复 → 结转月份并验证资金门锁定 → 合法反结转 → 维护银行资料并核对遮蔽 → 提交明确标识的支付模拟申请 → 切换角色 → 1280px、键盘、控制台和干净重启。

## 风险与阻塞

- 原文只有资金账户列表字段和“编辑”，没有新增字段、期初余额可改时点、停用/删除副作用或余额不足规则。
- “当期”没有期间选择、起止边界和跨月口径；结转原文允许反结转却没有入口、顺序、条件和后续数据处理。
- 银行列表与银行类型资金账户字段重叠，但没有定义一对一关系、创建联动、账号唯一性、删除规则和敏感信息可见范围。
- 在线支付涉及外部审批与真实资金能力；原文只有未开通/已开通和开通向导，不能由本地原型直接伪造已开通。
- 全局权限只写销售主管对资金“只读”、设置细权限只给功能点，未给结转权限和敏感银行账号的 baseline 角色映射。

## 已确认方案（2026-08-14）

| 决策 | 推荐方案 | 主要理由 |
|---|---|---|
| `DEC-FIN-006` | 允许新增账户；字段为名称、现金/银行/微信/支付宝类型、启用状态及首期期初余额。名称企业内唯一；已有流水或结转后类型不可改。停用后不可用于新资金动作，但历史和余额继续展示；不提供物理删除。 | 保留可追溯历史，又不给后续切片制造悬空引用。 |
| `DEC-FIN-007` | “当期”固定为受控 Mock 时钟所在的企业自然月，时区 Asia/Shanghai；页面可切换已存在期间并写入 URL，默认当前月，未来月份不可选。收入/支出只统计该月，当前/期末余额为截至选择月末（当前月截至当前时钟）的累计结果。 | 使列表、汇总和重置具有确定口径。 |
| `DEC-FIN-008` | 期初余额只在账户首个启用月份录入；在没有任何流水且首月未结转前可改，之后不可直接改，未来更正等待 `FIN-004` 形成可追溯调整单。 | 避免无流水重写历史余额。 |
| `DEC-FIN-009` | 所有账户默认禁止余额扣成负数；资金公开 command 在写流水前校验并整体拒绝。本原型不增加透支额度配置。 | 原文没有透支依据，保守规则最不易制造虚假资金。 |
| `DEC-FIN-010` | 保存企业账套启用月；只能从启用月开始按月连续结转，不允许未来月。空月可结转。一次结转原子冻结当月全部账户期末并生成下月期初；重复 requestId 幂等，失败不留下部分账户。 | 连续快照才能稳定解释期初、期末和锁定。 |
| `DEC-FIN-011` | 只允许反结转最新已结转月，必填 1～200 字原因；若其后已有任何资金流水或更晚结转则拒绝。成功原子删除派生的下月期初快照、解除锁定并保留不可变审计记录。 | 避免无来源的级联重算和历史漂移。 |
| `DEC-FIN-012` | 银行资料是独立主数据，但必须一对一关联一个 `bank` 类型资金账户；先建资金账户再维护银行资料，不自动创建或改余额。 | 明确资料与余额的单一所有者，避免两个“银行账户”余额不一致。 |
| `DEC-FIN-013` | 银行资料允许新增、编辑、停用；字段按原文，账号去空格后企业内唯一且 4～64 字符。被引用或有历史时不可删除，本切片统一不提供物理删除；停用后不可用于新业务。 | 满足管理入口并保留引用完整性，不臆造银行卡算法。 |
| `DEC-FIN-014` | 超级管理员和财务可见完整银行账号；销售主管即使可只读资金汇总，也只见后四位；业务员和仓库不可进入资金账户区域。日志永不记录完整账号。 | 兼顾全局只读权限和资金敏感性。 |
| `DEC-FIN-015` | 固定展示原文两个通道。点击开通只创建明确标记“原型模拟”的本地申请记录，状态显示“模拟申请中”，通道仍为“未开通”，不产生支付账户、余额或真实外部请求；已开通状态只可作为显式 baseline 展示。 | 可验证向导而不伪造第三方审批成功。 |
| `DEC-FIN-016` | 细权限为 `finance.view-accounts/manage-accounts/view-ledger/carryover/manage-banks/manage-payment-channels`。管理员和财务全量；销售主管只有 view-accounts/view-ledger 且银行账号遮蔽；业务员、仓库无权限。路由、UI、Store、Service 四层一致。 | 对齐模块只读和设置细权限，并补足原文遗漏的结转控制。 |
