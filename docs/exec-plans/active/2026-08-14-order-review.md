# ORD-003 订单审核与状态流转

- 类型：business-feature
- 功能：ORD-003
- 当前阶段：specification
- 状态：active
- 最近更新：2026-08-14

## 目标

从原始需求提取订单业务审核、财务审核、退回和特价审批的完整状态、角色、命令、副作用、失败恢复、Mock 与验收契约。任何会改变状态或跨域数据结果的缺失事实先登记人工决策；达到 `ready` 前不编写 `ORD-003` 业务代码。

## 范围与非目标

范围仅包括 `ORD-003`：单笔/批量业务审核、财务审核、待财务审核退回待订单审核、特价订单特殊审批，以及这些动作形成的订单状态与审计日志。新增/修改/分享已经由 `ORD-002` 提供；出库、发货、签收、差异单属于 `ORD-004`，取消、删除、作废若原始资料不能明确归入本切片则只记录边界，不自行实现。审核不预占或扣减库存，不提前形成出库或应收结果。

- `docs/references/requirements/02-订单模块.md §2.4`：审核、退回、状态名称与直接业务描述；`§2.1.5、§2.2.5、§2.3.1～§2.3.2、§8` 只用于核对批量审核、特价标记、详情入口与 `ORD-02/12`。
- `docs/references/requirements/01-整体架构与首页.md §2、§4～§5`：跨领域流程、全局交互与角色权限资料。

## 前置门禁

- `ORD-002` 已完成并有 passing 证据；订单保存的客户、商品、价格、金额、仓库、资金校验与历史快照不得在审核时重新猜算。
- `DEC-ORD-002` 已确认建单和审核均不预占、不扣库存；真实库存校验和扣减只归 `ORD-004`。
- `DEC-ORD-004` 已确认退回不释放预收占用；审核只能消费既有资金契约，不能发明新的资金副作用。
- `DEC-ORD-003` 仍为 open，特价分支在结论写回并将切片提升为 `ready` 前不得实现。

## 验证路径

- 逐项对照订单原文与既有订单聚合，形成动作矩阵、状态迁移、权限、批量原子性、审计日志、幂等/并发和页面反馈契约。
- `npm run verify:harness` 检查唯一 active plan、精确来源、字段准备度和 specification 阶段编码禁令。
- specification 检查点只允许修改 Harness 文档；人工决策写回后才可进入 implementation。
- 最终验证覆盖 normal、边界、失败、慢响应、空数据、无权限、并发/重复提交、批量混合状态、Mock 重置、1280px 与干净重启。

## 风险与阻塞

- 原文没有定义特价审批插入普通业务/财务审核链路的位置、角色、通过和拒绝后的状态。
- “审核通过进入待财务审核”与“特价特殊审批”可能形成串行或合并节点，不能按行业惯例猜测。
- 原文列出删除、作废、退回等详情动作，但 `§2.4` 只明确待财务审核可退回；其他终止动作的适用状态与副作用不能混入本切片。
- 批量审核只有入口描述，未明确部分成功、确认摘要、混合状态或并发变化的处理方式。
