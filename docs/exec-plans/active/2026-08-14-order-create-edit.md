# ORD-002 新增与修改订单

- 类型：business-feature
- 功能：ORD-002
- 当前阶段：specification
- 状态：active
- 最近更新：2026-08-14

## 目标

从原始需求提取新增订单、修改订单和订单分享的完整页面、字段、校验、计算、权限、状态、副作用、Mock 与验收契约。任何影响价格、库存、预收款、编号或历史快照的缺失事实先登记人工决策；达到 `ready` 前不编写 `ORD-002` 业务代码。

## 范围与非目标

范围仅包括 `ORD-002`：新增订单、符合条件订单的修改，以及订单分享。订单审核/退回/删除/作废属于 `ORD-003`，出库/发货/签收属于 `ORD-004`，退单/退款属于 `ORD-005`；商品、客户、库存和资金只通过已定义的公开 provider/command 契约协作，不在订单目录复制其主数据或提前实现后续切片。

- `docs/product-specs/orders.md`：订单领域现有事实、`ORD-001` 快照模型和本切片契约写回位置。

- `docs/references/requirements/02-订单模块.md §2.2、§2.5`：新增/编辑表单、订单分享及直接业务描述。
- `docs/references/requirements/01-整体架构与首页.md §2、§4、§5`：跨领域流程、全局交互、角色与细粒度权限。

## 验证路径

- 逐项对照订单原文 `§2.2`、`§2.5`，形成页面、字段、校验、计算、权限、状态、失败语义和自动/人工验收追踪。
- 核对客户、商品、价格、铺货模板、库存、资金及设置公开边界，缺少 provider 时明确 `unavailable` 或登记阻塞，禁止猜值。
- `npm run verify:harness` 检查唯一 active plan、精确来源、决策门和 specification 阶段编码禁令。
- specification 检查点只允许修改 Harness 文档；进入 implementation 后再分领域核心、Runtime/UI、最终验收建立独立 Git 回退点。
- 最终验证必须覆盖 normal、empty、error、slow、permission-denied、provider 部分失败、金额/数量/日期边界、并发修改、Mock 重置、1280px 和干净重启。

## 风险与阻塞

- 原文包含客户价、等级价、会员折扣、客户分类折扣、行折扣、手工价、整单折扣、促销和优惠券，但没有给出完整组合顺序。
- 原文要求自动占用预收款，却没有金额、更新、失败及释放规则；资金基础能力尚未完成。
- 原文说创建订单不预占库存，但索引仍保留库存预占决策，需要明确本切片只做可售校验还是产生库存副作用。
- “保存并结算出库”跨越审核、资金和出库切片，不能据按钮名称提前跳过状态机。
- 订单号、可编辑状态、重复商品、舍入、地址快照、附件、批量录入和分享过期等规则需要从原文确认或登记决策。
