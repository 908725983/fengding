## 目标

在不削弱业务事实追踪、金额/库存一致性、权限和跨模块闭环的前提下，移除原始需求未要求的逐页重复验收，把后续工作改为风险分级和可恢复的业务批次执行。

## 范围与非目标

范围：计划类型、验证分级、页面验收边界、状态唯一来源、剩余切片批次、Harness 机械检查、当前 `INV-003` 恢复点。

非目标：删除既有业务实现或历史 completed 证据；降低金额、库存、权限和跨模块事务测试；在本计划中修复共享 Mock Runtime；改变原始业务字段或规则。

## 事实来源

- `docs/references/requirements/01-整体架构与首页.md §1～§5`：PC 管理后台、核心闭环、分页、空状态和权限基线。
- `docs/references/requirements/02-订单模块.md`～`08-设置模块.md`：全部业务功能范围。
- `docs/product-specs/index.md`：功能来源、准备度和业务决策门。
- `docs/PLANS.md`、`docs/RELIABILITY.md`、`docs/FRONTEND.md`：当前重复执行要求。
- `scripts/verify-harness.mjs`：机械门禁实际行为。

## 前置门禁

- 原始需求快照和哈希保持不变。
- 当前 `INV-003` 业务计划继续作为唯一业务现场，本计划不得改写其业务结论。
- 只删除或合并工程流程，不删除原文明确要求的分页、空状态、导出、权限或核心流程。

## 验证路径

1. Harness 文档一致性：批次计划、风险等级、适用场景和唯一状态源互相一致。
2. 机械检查：支持 `business-batch` 的多个功能 ID，逐个验证来源、准备度、依赖和决策门。
3. 目录审计：`PRD-006` 因只有一句规则进入 blocked，其余切片仍覆盖原始需求。
4. 回归：运行 `npm run verify:harness`、`git diff --check`；本计划不改业务运行代码，不重复执行全量业务测试和构建。

## 风险与阻塞

- 批次不能成为绕过单个功能字段契约和依赖门的方式。
- 共享 Runtime、原子回滚和高风险并发验证必须保留。
- 历史 completed 计划保留原验收事实，不回写新标准。
- 当前业务计划的恢复点已经落后于代码现场，需要只同步事实，不能重新执行已完成步骤。
