## 目标

实现加工配方、加工计划、加工单、加工领料、加工退料和原料出成率统计，使加工从 BOM 快照开始，经领料扣减原料、退回余料和完工增加成品库存形成可追溯闭环；所有数量、批次、成本、月份锁、盘点锁和权限继续复用库存领域既有事实，不允许页面直接修改余额。

## 范围与非目标

- 范围：`INV-004` 六个页面、Repository/Service/Store/View、加工状态机、库存流水、成本分摊、权限、CSV fake adapter 和 L3 自动证据。
- 销售订单只作为“按订单创建计划”的只读来源；加工不自动发货、不改变订单履约状态、不创建应收应付。
- 不实现生产排程、工序/工时、设备、人力、质检、委外加工、真实 ERP 接口和会计凭证。
- 不提前实现 `INV-005` 分拣配送或 `INV-006` 库存统计。

## 原文已明确的范围

1. 加工配方包含名称、唯一编码、方式（组合/拆卸/组装）、分类、备注、成品/半成品明细和原料明细；明细包含商品、规格、单位、数量和默认仓库。
2. 加工计划支持按销售订单和直接创建，状态为待处理/处理中/已完成/已取消；按订单时按订单商品匹配配方。
3. 加工单状态为待领料/领料中/加工中/已完成，并关联配方、可选计划、计划数量、实际数量和加工仓库。
4. 加工领料单确认出库后扣减原料库存；退料单确认入库后增加原料库存；完工增加成品库存。
5. 出成率统计展示加工单、配方、成品、原料、配方用量、实际用量和出成率，原文公式为“实际产出÷配方预计产出×100%”。

## 实现设计（确认后执行）

1. 在 Inventory state/schema/repository 增加配方版本、计划、加工单、领料、退料和完工产出事实；所有关联保存稳定 ID 与业务快照。
2. Service 先实现纯计算和状态命令，再通过已有 Inventory command 完成 FIFO 出库、原批次退料和产出入库；跨实体写入使用快照回滚与 requestId 幂等。
3. 共享 Runtime 为按订单计划注入窄只读 Order provider，不复制订单 fixture，不从 Inventory 反向修改订单。
4. Store 只编排 Service；六个 View 复用库存二级导航和现有设计令牌，不增加领域内 ScenarioBar。
5. 自动测试优先覆盖 BOM 缩放、部分领料、退料守恒、成本分摊、完工原子回滚、锁/月结、重复请求、并发和权限；页面测试覆盖核心表单与状态。

## 验证路径

- 从新建配方开始，创建直接计划与加工单，分两次 FIFO 领料，退回余料，完工入库，核对原料减少量、退料增加量、成品增加量、成本和出成率守恒。
- 按订单创建计划时核对订单候选、SKU 配方匹配、剩余数量和无订单副作用。
- 验证库存不足、过期批次、盘点锁、已结转月份、重复 requestId、旧 version 和完工中途失败均不留下半完成事实。
- 代表性 1280px 浏览器旅程验证入口、表单、列表/详情、权限遮蔽、错误重试、无整页横向溢出和控制台无 warning/error。
- `INV-004/005/006` 各自保留独立回退点；库存扩展批次末尾统一执行全量验证、Mock reset 与干净重启。本切片开发中只跑最小相关测试，归档前保留本切片 L3 专项证据。

## 风险与阻塞

- 原文没有解释多产出时“计划数量”和成本如何分配；不确认 `DEC-INV-047/057` 会直接造成库存价值不可复算。
- 原文状态图中“领料完成（生成领料单）”的发生时点与独立领料页面存在歧义；按 `DEC-INV-053/054` 固定为领料单确认后推动状态。
- 原文同时要求独立退料单和“完工生成退料单”；按 `DEC-INV-055/056` 允许过程退料，并在完工命令中原子处理最后退料，避免重复入库。
- 按订单计划是跨域只读来源；若共享 Runtime 没有符合条件订单，页面必须显示真实空态，不使用加工模块自造订单。
