# 原型实现顺序

- 状态：Accepted
- 最近更新：2026-08-11

## 目标

按业务依赖建立可重复验收的纵向切片，避免先画大量页面、后补业务事实。当前 Harness 和应用壳已完成；尚未开始业务功能。

## 阶段与出口

1. 销售基础资料：客户档案 → 商品/SKU → 价格 → 授权 → 库存基础。出口是能回答指定客户可订什么、按什么价格和单位、是否有可用库存。
2. 销售与资金：订单列表/建单 → 审核 → 出库发货 → 应收与收款核销 → 退单 → 销售统计。出口是销售黄金旅程可从固定基线重复执行。
3. 采购与库存：供应商 → 补货 → 采购单/入库 → 应付核销 → 退采 → 转仓/盘点/加工/分拣 → 统计。出口是所有库存变化能追溯到单据和流水。
4. 组织与运营：商品运营、客户经营、营销、角色权限、基础资料和日志。外部能力继续使用 fake adapter。
5. 首页聚合：最后实现待办、经营概览、预警与公告，确保指标来源和跳转依赖真实领域事实。

## 当前下一切片

下一项是“客户档案、分类与标签”。开始时创建 `docs/exec-plans/active/YYYY-MM-DD-customer-foundation.md`，从客户规格与原始需求提取本切片所需字段、状态和验收，不提前扩写后续功能。

## 暂不实施

- 商家模块、独立数据分析：缺少独立详细需求。
- 真实支付、地图、GPS、企微、消息、AI、打印物流：原型阶段只模拟可见行为。
