# 原型实现顺序

- 状态：Accepted
- 最近更新：2026-08-11

## 职责

本文件只决定“先做什么、为什么、阶段如何退出”。`../product-specs/index.md` 是全部功能、来源、依赖和规格准备度的唯一目录；`../QUALITY_SCORE.md` 是当前质量与完成证据入口；`../exec-plans/active/` 保存当前切片现场。

## 切片开工门

业务切片进入代码实现前必须同时满足：

1. 功能 ID 存在于产品规格索引，且所有依赖已有 passing 证据。
2. 字段准备度为 `ready`，对应领域规格存在完整的“`<功能ID> 字段与交互契约`”。
3. 所有阻塞该切片的人工决策已变为 `decided`；未受影响的部分可以继续规格提取。
4. `docs/exec-plans/active/` 中存在唯一业务 active plan，写明功能 ID、阶段、精确来源和验证路径。
5. `npm run verify:harness` 基线通过。

任何一项不满足，都不允许为了展示进度先写一个“看起来像完成”的页面。

## 阶段零：工程基线（已完成）

1. `HNS-001` Harness 工程基线。
2. `SHELL-001` PC 管理后台应用壳。

出口：仓库可初始化、启动、验证和干净重启；未实现模块不会伪装成完成。

## 阶段一：销售基础事实

严格顺序：

1. `CUS-001` 客户档案、分类与标签。
2. `PRD-001` 商品、SKU 与多单位。
3. `PRD-002` 价格体系与调价。
4. `PRD-003` 商品授权。
5. `INV-001` 库存查询、仓库、库位与批次。

顺序理由：订单必须先能回答“客户是谁、商品是什么、使用什么单位和价格、客户是否有权购买、出库时是否有可用库存”。客户编码/状态、单位换算、授权冲突和库存状态边界分别受产品目录中的决策门约束。原始需求没有库存预占规则，禁止在本阶段自行添加预占；仅实现已确认的出库扣减。

阶段出口：对指定客户和 SKU，可解释地返回授权、价格来源、单位和当前可用库存；所有结果来自领域 Service，而不是页面临时数组。

## 阶段二：销售与收款闭环

1. `ORD-001` 客户订单列表与详情。
2. `ORD-002` 新增与修改订单。
3. `ORD-003` 订单审核与状态流转。
4. `ORD-004` 销售出库、发货与差异。
5. `FIN-003` 资金账户、银行与结转基础。
6. `FIN-001` 客户应收、收款与核销。
7. `ORD-005` 客户退单与退款。
8. `ORD-006` 订单与销售统计。

进入 `ORD-002` 前解决价格组合、客户状态、单位换算、授权冲突和预收占用；进入 `ORD-003` 特价分支前解决特殊审批；连接 `ORD-004` 与 `FIN-001` 前解决应收形成时点；连接退货、入库和退款前解决相应跨域决策。未决时可完成互不依赖的页面和只读契约，但不得伪造跨域结果。

阶段出口：固定 Mock 基线可以重复完成“选客户与商品 → 建单 → 审核 → 出库/发货 → 应收 → 收款核销”，失败不会留下半完成库存或资金状态。

## 阶段三：采购、库存与资金闭环

采购主线：

1. `PUR-004` 供应商与直送供应。
2. `PUR-001` 补货分析与快速采购。
3. `PUR-002` 采购订单与入库。
4. `FIN-002` 供应商应付、付款与核销。
5. `PUR-003` 采购退单。
6. `PUR-005` 采购统计。

库存与资金扩展（依赖满足后按以下顺序）：

7. `INV-002` 转仓与其他出入库。
8. `INV-003` 盘点、成本调整与库存结转。
9. `INV-004` 加工管理。
10. `INV-005` 分拣与配送。
11. `INV-006` 库存统计。
12. `FIN-004` 退款、转账与其他收支。
13. `FIN-005` 机构收款与资金统计。

进入补货结果前解决补货公式，进入采购状态机前统一订单/入库状态表达，进入带成本入库前解决加权成本口径，进入应付集成前解决应付形成时点；进入采购退单校验前确认是否强制关联原采购单。阶段出口是“库存/订单需求 → 采购 → 入库 → 应付 → 付款核销”可重复，所有库存和资金变化都能追溯到单据。

## 阶段四：组织与运营扩展

设置基础：

1. `SET-001` 公司、部门与公告。
2. `SET-002` 角色、权限与员工。
3. `SET-003` 区域与共享仓库资料。
4. `SET-004` 系统日志。

商品运营：

5. `PRD-005` 商品辅助资料。
6. `PRD-004` 铺货方案与订单模板。

客户经营与营销：

7. `CUS-002` 商机与客户常购商品。
8. `CUS-003` 会员等级与权益。
9. `CUS-004` 客户地图与公海。
10. `CUS-005` 外勤拜访。
11. `CUS-006` 优惠券、促销与内容获客。
12. `CUS-007` 积分管理。
13. `CUS-008` 企微运营模拟。
14. `CUS-009` 商城运营原型。
15. `CUS-010` 营销分析与拉新提成。

只要产品规格索引中的依赖已通过，设置、商品运营和客户经营三条子线可以调整先后，但同一时间仍只推进一个实现切片。实现默认角色前必须解决“部分权限”的细权限映射；企微、地图、消息、AI、在线支付和真实文件继续使用 fake adapter。

阶段出口：模拟角色看到正确菜单和操作，配置由唯一领域事实驱动，运营功能不绕过商品、订单或资金规则。

## 阶段五：首页聚合

1. `DASH-001` 首页待办与经营概览。

首页最后实现，因为它依赖客户营销、资金统计、库存统计、订单统计和角色权限。每个指标必须有来源、时间范围、单位、计算口径和目标跳转；原始需求没有定义的指标不得凭经验补齐。

## 暂停范围

- `MER-001` 商家模块：只有模块名称，无页面和行为需求。
- `ANA-001` 独立数据分析模块：只有入口名称和分散统计页，无独立指标体系。
- 真实支付、地图/GPS、企微、消息、AI、打印物流：原型只验证明确标识的模拟交互。
