# 前端设计规范

## 设计方向

采用高信息密度、表格驱动、冷色调的 B2B 管理后台风格。参考产品提供的是风格线索，不是临摹模板。本项目使用自己的名称、图标、配色比例、尺寸和文案。

关键词：克制、清晰、紧凑、可扫描、状态明确。

## 视觉 Token

| 用途 | Token | 基准值 |
|---|---|---|
| 侧栏底色 | `--color-sidebar` | `#1f2a3d` |
| 品牌主色 | `--color-primary` | `#168c91` |
| 主色浅底 | `--color-primary-soft` | `#e8f6f5` |
| 页面底色 | `--color-page` | `#f5f7fa` |
| 表头底色 | `--color-table-head` | `#f0f3f7` |
| 边框 | `--color-border` | `#e2e7ed` |
| 主文字 | `--color-text` | `#202936` |
| 次文字 | `--color-muted` | `#697586` |
| 成功/警告/危险 | semantic tokens | `#278764 / #d98b20 / #d64545` |

圆角以 6px 为主；阴影只用于浮层；间距采用 4px 基数。控制高度 36–40px，常规表格行 48–56px。PC 设计基准宽度 1440px，最低支持 1280px。普通管理后台页面不承担 390px 移动适配；只有公开分享页、商城/小程序预览或原文明确的移动页面单独验收窄屏。

## 应用骨架

```text
深色主导航 | 顶部工作区与全局动作
           | 页面标题 + 页面级操作
           | 核心筛选 / 展开更多筛选
           | 数据主体（表格优先）
           | 汇总 + 分页
```

- 侧栏建议 176px，可折叠；当前项使用左侧指示条和浅色选中底，不使用整块高饱和色。
- 顶栏 56px，显示系统名、当前原型场景与用户。
- 页面内容保留 20–24px 外边距。主要操作靠右，筛选与内容左对齐。
- 鼠标悬停或键盘聚焦侧栏模块打开模块总菜单浮层；菜单按业务分组列出该模块全部可访问入口，当前页面高亮，鼠标离开侧栏和菜单面板、点击入口或 `Esc` 后关闭。菜单清单唯一维护于 `src/app/module-navigation.ts`，不得在页面中再复制一份入口事实。

## 组件与交互规则

- 列表：固定表头；金额右对齐；数字使用等宽数字；状态不能只靠颜色表达。
- 筛选：默认展示 3–5 个高频条件，其他条件折叠；“查询”和“重置”行为固定。
- 表单：按业务语义分区；必填、单位、计算来源明确；离开未保存表单需提示。
- 详情：页首显示单号、主状态、关键金额和下一步动作；日志与关联单据可追溯。
- 弹窗：只处理短任务；复杂新增/编辑使用独立页面或抽屉。
- 空状态：区分无数据、无搜索结果、无权限和加载失败，并给出下一步。
- 模拟外部能力时必须显示“原型模拟”，不得伪装真实成功。
- Mock 场景和角色切换属于开发工具，不是业务页面字段；新增页面不得复制领域级场景条。需要浏览器调试时由应用壳提供一个仅开发环境可见的控制入口，正式页面不展示“原型控制”。

## 页面开工门与字段忠实度

- 业务页面只有在对应功能的字段准备度为 `ready`、领域规格存在完整字段与交互契约后才能实现。
- 页面名称、筛选项、列、Tab、表单字段、必填、默认值、选项、排序、分页、按钮、权限和状态都从契约读取；原文没有定义时不允许以“后台一般如此”补齐。
- 视觉层可以决定间距、换行、响应式折叠和组件复用，但不能改变业务字段含义、把两个状态合并、隐藏未解决的错误或新增保存副作用。
- 契约要求但当前切片不实现的内容必须明确列入非目标并显示为未实施，不得用无响应按钮占位。
- 字段展示需区分原始值、计算值、格式化值和单位；金额、数量、日期、电话、地址等不得在组件内自行猜测格式或精度。

## 状态表达

统一使用 `StatusBadge` 语义：neutral、info、success、warning、danger。每个状态由规格定义标签与允许动作，不允许组件自行推导状态流转。

## 文案

- 使用业务人员熟悉的“订单、出库、核销”等词，不以代码术语代替。
- 危险确认文案必须说清对象和结果，例如“作废后库存不会自动恢复”。
- 未实现功能标记“规划中”，不能使用无响应按钮冒充完成。

## 页面验收清单

- 每个业务批次选择一个代表性 1280px 页面检查主要操作；复用同一壳、表格和表单结构的页面不逐页重复。表格允许内部横向滚动但不遮挡分页。
- 键盘焦点可见；表单控件有名称；颜色对比足以辨识。公共组件已覆盖的行为不在每页重复手工验证。
- `normal` 和适用的 `empty` 必须符合契约；`error/retry`、`permission-denied`、`partial-failure`、`concurrent`、`unavailable` 按 `RELIABILITY.md` 风险与适用性选择，不要求每页凑齐全部状态。
- 不出现参考产品的 Logo、品牌名、原文案或像素级复刻。
- 页面只通过 composable/store 获取数据，不直接导入 fixture。
- 所有可见字段、操作和状态都能回指字段契约；截图仅用于关键视觉证据，不能替代契约验收。
