# 设计文档入口

这里记录“为什么这样设计”和跨功能仍需成立的约束；用户可见行为写入 `product-specs/`，系统依赖边界写入根目录 `ARCHITECTURE.md`，当前任务步骤写入 `exec-plans/active/`。

## 何时阅读或更新

- 改变领域边界、核心模型、跨领域流程或长期实现顺序时。
- 一个决定会影响多个后续功能，且仅看代码无法理解理由时。
- 同类评审意见反复出现，需要沉淀原则或转成机械检查时。

新文档应短小且只覆盖一个决策区域，并登记到 [design-docs/index.md](design-docs/index.md)。已经成为硬性边界的结论要同步升级到 `ARCHITECTURE.md` 或自动验证。
